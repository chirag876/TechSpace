1. Conditional Statements

Basic

Q1. What are the different conditional statements available in C#?

Answer:

  • if / else if / else
  • switch / switch expression (C# 8+)
  • Ternary operator ? :
  • Null-coalescing operator ??
  • Null-conditional operator ?.

Q2. What is the difference between if-else if and switch statement?

Answer:

Feature if-else if switch
Works on Any boolean expression Constant values (int, string, enum, etc.)
Pattern matching Limited Full (C# 7+)
Readability Lower for many branches Higher for many cases
Fall-through Not applicable Requires explicit break or goto case 
// if-else
if (x == 1) Console.WriteLine("One");
else if (x == 2) Console.WriteLine("Two");

// switch
switch (x)
{
    case 1: Console.WriteLine("One"); break;
    case 2: Console.WriteLine("Two"); break;
}

Q3. What is a ternary operator? Give an example.

Answer: It’s a shorthand for if-else returning a value.

int age = 20;
string result = (age >= 18) ? "Adult" : "Minor";

Syntax: condition ? value_if_true : value_if_false

Q4. Can we use switch on a string in C#?

Answer: Yes. C# allows switch on string, int, char, enum, and with pattern matching in C# 7+, even on types.

string day = "Monday";
switch (day)
{
    case "Monday": Console.WriteLine("Start of week"); break;
    default: Console.WriteLine("Other day"); break;
}

Q5. What happens if no default case is present in a switch and no case matches?

Answer: Nothing happens — the switch block is simply skipped. No exception is thrown.

Intermediate

Q6. What is a switch expression (C# 8+)? How is it different from a switch statement?

Answer: switch expression is concise and returns a value directly.

// switch statement
string result;
switch (day)
{
    case "Monday": result = "Weekday"; break;
    default: result = "Other"; break;
}

// switch expression (C# 8+)
string result = day switch
{
    "Monday" => "Weekday",
    "Saturday" or "Sunday" => "Weekend",
    _ => "Other"  // _ is the discard/default
};

Q7. What is pattern matching in switch (C# 7+)?

Answer: You can match on type, conditions, and properties.

object obj = 42;
switch (obj)
{
    case int i when i > 0:
        Console.WriteLine($"Positive int: {i}");
        break;
    case string s:
        Console.WriteLine($"String: {s}");
        break;
    case null:
        Console.WriteLine("Null");
        break;
    default:
        Console.WriteLine("Other");
        break;
}

Q8. Can switch cases fall through in C#?

Answer: By default, no. Unlike C/C++, C# does not allow implicit fall-through between non-empty cases. Each non-empty case must end with break, return, throw, or goto case.

// COMPILE ERROR - implicit fall-through not allowed
case 1:
    Console.WriteLine("One");
case 2:  // Error!
    ...

// VALID - explicit goto case
case 1:
    Console.WriteLine("One");
    goto case 2;
case 2:
    Console.WriteLine("Two");
    break;

// VALID - empty cases can fall through
case 1:
case 2:
    Console.WriteLine("One or Two");
    break;

Q9. What is the ?? (null-coalescing) operator?

Answer: Returns the left operand if it’s not null; otherwise returns the right operand.

string name = null;
string result = name ?? "Default";  // result = "Default"

// ??= (C# 8) — assign only if null
name ??= "Fallback";

Q10. What is the ?. (null-conditional) operator?

Answer: Safely accesses members/methods without throwing NullReferenceException.

string name = null;
int? length = name?.Length;  // null, not exception

// Chaining
var city = person?.Address?.City;  // null if any part is null

Advanced

Q11. What is the difference between == and .Equals() in conditionals with strings?

Answer:

  • == for strings in C# is overloaded to compare by value (content).
  • .Equals() also compares by value but can be customized.
  • With object type, == checks reference equality.
string a = "hello";
string b = new string("hello".ToCharArray());

Console.WriteLine(a == b);         // True (value comparison)
Console.WriteLine(object.ReferenceEquals(a, b)); // False (different refs)

Q12. Explain when guard in switch expressions (C# 9+).

Answer:

int score = 75;
string grade = score switch
{
    >= 90 => "A",
    >= 75 => "B",
    >= 60 => "C",
    _ => "F"
};

In switch statements, when is used as a guard clause:

case int n when n > 0:
    Console.WriteLine("Positive");
    break;

Q13. Can you use if inside a switch and vice versa? Any issues?

Answer: Yes, both are fully nestable. No issues, but deeply nested logic should be refactored for readability. Common in real-world code.

Q14. What is short-circuit evaluation in C# conditionals?

Answer: In && and ||, C# evaluates left-to-right and stops as soon as the result is determined.

// If IsNull() returns true, Divide() is never called
if (IsNull(x) || Divide(x) > 0) { ... }

// If IsPositive() returns false, GetValue() is never called
if (IsPositive(x) && GetValue(x) > 10) { ... }

Use & and | (non-short-circuit) if both sides must always be evaluated.

2. Loops

Basic

Q15. What are the types of loops in C#?

Answer:

  • for — when iteration count is known
  • while — when condition is checked before execution
  • do-while — when body must execute at least once
  • foreach — iterating over collections implementing IEnumerable

Q16. What is the syntax of a for loop in C#?

Answer:

for (int i = 0; i < 10; i++)
{
    Console.WriteLine(i);
}
// Sections: initialization; condition; iterator

Q17. What is the difference between while and do-while?

Answer:

while do-while
Condition check Before body After body
Minimum executions 0 1 
// while — may never execute
while (false) { Console.WriteLine("Never"); }

// do-while — executes at least once
do { Console.WriteLine("Once"); } while (false);

Q18. What is a foreach loop? What must the collection implement?

Answer: foreach iterates over any type implementing IEnumerable or IEnumerable<T>.

int[] nums = {1, 2, 3};
foreach (int n in nums)
{
    Console.WriteLine(n);
}

Under the hood, it calls GetEnumerator(), then MoveNext() and Current.

Q19. Can you modify a collection inside a foreach?

Answer: No. Modifying the collection while enumerating throws InvalidOperationException. Use a regular for loop or create a copy.

// WRONG
foreach (var item in list)
    list.Remove(item); // InvalidOperationException at runtime

// CORRECT
for (int i = list.Count - 1; i >= 0; i--)
    if (condition) list.RemoveAt(i);

Q20. How do you write an infinite loop in C#?

Answer:

while (true) { }
for (;;) { }
do { } while (true);

Intermediate

Q21. What is the difference between for loop and foreach loop in terms of performance?

Answer:

  • For arrays, for is marginally faster because foreach uses an enumerator object (though the JIT often optimizes this away).
  • For List<T>, both are similar.
  • For IEnumerable (LINQ queries, deferred execution), foreach is the only practical choice.
  • Prefer foreach for readability unless performance profiling shows a difference.

Q22. Can foreach work on a custom class? How?

Answer: Yes, implement IEnumerable<T> and IEnumerator<T>, or use the duck-typing pattern (a GetEnumerator() method returning something with MoveNext() and Current).

class NumberRange : IEnumerable<int>
{
    private int _start, _end;
    public NumberRange(int start, int end) { _start = start; _end = end; }

    public IEnumerator<int> GetEnumerator()
    {
        for (int i = _start; i <= _end; i++)
            yield return i;
    }
    IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();
}

foreach (int n in new NumberRange(1, 5))
    Console.WriteLine(n); // 1 2 3 4 5

Q23. What is yield return and how does it relate to loops?

Answer: yield return creates a lazy iterator. The method body is paused at each yield return and resumed on the next MoveNext() call.

IEnumerable<int> GetEvenNumbers(int max)
{
    for (int i = 0; i <= max; i += 2)
        yield return i;  // Pauses here, resumes on next iteration
}

foreach (int n in GetEvenNumbers(10))
    Console.WriteLine(n);  // 0 2 4 6 8 10

Q24. What happens to variables declared inside a loop? Are they re-initialized each iteration?

Answer: Yes. Variables declared inside the loop body are created fresh each iteration and go out of scope at the end of each iteration. This is important when capturing loop variables in lambdas.

// PROBLEM - closure captures variable i by reference
var actions = new List<Action>();
for (int i = 0; i < 3; i++)
    actions.Add(() => Console.WriteLine(i));
actions.ForEach(a => a()); // Prints 3 3 3 (not 0 1 2!)

// FIX - capture a local copy
for (int i = 0; i < 3; i++)
{
    int copy = i;
    actions.Add(() => Console.WriteLine(copy));
}
// Prints 0 1 2

Note: foreach in C# 5+ already creates a fresh variable per iteration — this issue is specific to for.

Q25. Can a for loop have multiple initialization or iterator expressions?

Answer: Yes, separate them with commas.

for (int i = 0, j = 10; i < j; i++, j--)
    Console.WriteLine($"i={i}, j={j}");

Q26. What is the difference between i++ and ++i in a loop context?

Answer:

  • i++ — post-increment: returns the old value, then increments.
  • ++i — pre-increment: increments first, returns the new value.

In a for loop’s iterator section, both have the same effect on the loop itself (increment happens after body). The difference matters only when the value is used in an expression.

int a = 5;
int b = a++;  // b = 5, a = 6
int c = ++a;  // a = 7, c = 7

Advanced

Q27. Can you iterate over a Span<T> or Memory<T> with foreach?

Answer: Yes. Span<T> supports foreach via a built-in enumerator (stack-allocated, no heap allocation). Memory<T> also supports foreach via .Span.

Span<int> span = stackalloc int[] { 1, 2, 3 };
foreach (int n in span)
    Console.WriteLine(n);

Q28. What is the impact of await inside a loop?

Answer: Each iteration awaits sequentially — the loop does not proceed to the next iteration until the awaited task completes. If parallelism is needed, collect tasks first and use Task.WhenAll.

// Sequential (one at a time)
foreach (var url in urls)
    await FetchAsync(url);

// Parallel (all at once)
var tasks = urls.Select(url => FetchAsync(url));
await Task.WhenAll(tasks);

Q29. How does LINQ’s lazy evaluation interact with loops?

Answer: LINQ queries are deferred — they execute only when enumerated (e.g., in a foreach). If the underlying collection changes between query definition and enumeration, results reflect the changed state.

var list = new List<int> { 1, 2, 3 };
var query = list.Where(x => x > 1);  // Not executed yet
list.Add(5);
foreach (var n in query)
    Console.WriteLine(n);  // 2, 3, 5 — includes 5!

3. break Statement

Basic

Q30. What does break do in C#?

Answer: break immediately exits the innermost enclosing loop (for, while, do-while, foreach) or switch statement.

for (int i = 0; i < 10; i++)
{
    if (i == 5) break;
    Console.WriteLine(i);  // Prints 0 1 2 3 4
}

Q31. Can break be used outside a loop or switch?

Answer: No. Using break outside a loop or switch is a compile-time error.

Q32. What happens when break is used in nested loops?

Answer: It only exits the innermost loop. Outer loops continue.

for (int i = 0; i < 3; i++)
{
    for (int j = 0; j < 3; j++)
    {
        if (j == 1) break;  // Only exits inner loop
        Console.WriteLine($"{i},{j}");
    }
}
// Output: 0,0  1,0  2,0

Intermediate

Q33. How do you break out of a nested loop in C# (since there’s no labeled break like Java)?

Answer: Options include:

  1. Use goto with a label (the most direct C# equivalent of labeled break)
  2. Use a flag variable
  3. Refactor to a method and use return
// Option 1 - goto
for (int i = 0; i < 3; i++)
    for (int j = 0; j < 3; j++)
        if (i == 1 && j == 1) goto Done;
Done:
    Console.WriteLine("Broke out");

// Option 2 - flag
bool found = false;
for (int i = 0; i < 3 && !found; i++)
    for (int j = 0; j < 3; j++)
        if (i == 1 && j == 1) { found = true; break; }

// Option 3 - method (cleanest)
SearchMatrix();
void SearchMatrix()
{
    for (int i = 0; i < 3; i++)
        for (int j = 0; j < 3; j++)
            if (i == 1 && j == 1) return;
}

Q34. Does break work inside a switch that’s inside a loop?

Answer: The break inside switch exits the switch, not the loop. To exit the loop from inside a switch, you need an additional break or use goto/flag.

for (int i = 0; i < 5; i++)
{
    switch (i)
    {
        case 3:
            break;  // Exits switch, NOT the for loop
    }
    Console.WriteLine(i);  // Still prints 0 1 2 3 4
}

Advanced

Q35. Is there any performance difference between using break early vs. letting a loop finish naturally?

Answer: Yes. Early break (short-circuit) avoids unnecessary iterations — crucial for large collections. Always prefer early exit when the answer is found. This is the core idea behind search algorithms.

4. continue Statement

Basic

Q36. What does continue do?

Answer: continue skips the rest of the current iteration and moves to the next iteration of the loop.

for (int i = 0; i < 5; i++)
{
    if (i == 2) continue;
    Console.WriteLine(i);  // Prints 0 1 3 4
}

Q37. What is the difference between break and continue?

Answer:

break continue
Effect Exits the loop entirely Skips current iteration only
Loop continues? No Yes

Q38. Does continue work in foreach?

Answer: Yes.

foreach (int n in new[] { 1, 2, 3, 4, 5 })
{
    if (n % 2 == 0) continue;
    Console.WriteLine(n);  // 1 3 5
}

Intermediate

Q39. Where does control go after continue in a for loop vs. a while loop?

Answer:

  • In a for loop: control goes to the iterator expression (i++), then checks the condition.
  • In a while loop: control goes directly to the condition check.
// for — iterator runs after continue
for (int i = 0; i < 5; i++)
{
    if (i == 2) continue;  // i++ still runs, so i becomes 3 next
    Console.WriteLine(i);
}

// while — condition checked directly after continue
int x = 0;
while (x < 5)
{
    x++;
    if (x == 3) continue;  // Goes back to while(x < 5)
    Console.WriteLine(x);
}

Q40. Can continue cause an infinite loop?

Answer: Yes, if in a while loop and the increment/change happens after the continue.

int i = 0;
while (i < 5)
{
    if (i == 2) continue;  // INFINITE LOOP — i never becomes > 2
    i++;
}

Fix: Increment before continue.

Q41. What does continue do in nested loops?

Answer: It applies to the innermost enclosing loop only.

for (int i = 0; i < 3; i++)
    for (int j = 0; j < 3; j++)
    {
        if (j == 1) continue;  // Skips j=1, outer loop unaffected
        Console.WriteLine($"{i},{j}");
    }
// 0,0  0,2  1,0  1,2  2,0  2,2

5. goto Statement

Basic

Q42. What is goto in C#?

Answer: goto transfers control unconditionally to a labeled statement, a case in a switch, or the default case.

goto MyLabel;
Console.WriteLine("Skipped");
MyLabel:
Console.WriteLine("Jumped here");

Q43. Where can goto be used in C#?

Answer: Three valid uses:

  1. Jump to a label in the same method
  2. goto case X; in a switch — jumps to another case
  3. goto default; in a switch — jumps to default case
switch (x)
{
    case 1:
        Console.WriteLine("One");
        goto case 2;  // Falls through to case 2
    case 2:
        Console.WriteLine("Two");
        break;
}

Q44. Is goto considered bad practice in C#?

Answer: Generally yes. It makes code harder to read and maintain (spaghetti code). However, goto case in switch statements is a recognized and sometimes the only clean way to express fall-through in C#. Avoid in loops unless breaking out of deeply nested structures where no cleaner option exists.

Intermediate

Q45. Can goto jump into a block (e.g., inside an if or for)?

Answer: No. goto can only jump to labels in the same scope or an enclosing scope. Jumping into a block (forward into a nested scope) is a compile-time error.

goto Inside;  // COMPILE ERROR — cannot jump into block
if (true)
{
    Inside:
    Console.WriteLine("Here");
}

Q46. Can goto exit a finally block?

Answer: No. goto cannot transfer control out of a finally block. Attempting this is a compile-time error.

Q47. Is there any legitimate modern use of goto in C#?

Answer: Yes — a few accepted scenarios:

  1. Breaking out of nested loops (no labeled break in C#)
  2. goto case in switch for intentional fall-through
  3. State machine code generated by compilers (async/await internally uses goto-like IL jumps)
  4. Retry patterns (though do-while is preferred)

Advanced

Q48. How does goto relate to the async/await state machine under the hood?

Answer: When the compiler transforms async methods, it generates a state machine that uses goto-like jumps (in IL: br, brtrue, beq) to resume execution after await points. The generated code resembles a switch-case with goto semantics, which is why understanding goto helps in understanding IL and compiler output.

6. pass Equivalent in C#

Conceptual

Q49. C# doesn’t have a pass keyword like Python. What is the equivalent?

Answer: C# doesn’t need pass because:

  • Empty blocks {} are valid syntactically
  • A semicolon ; acts as an empty statement
// Empty if block
if (condition) { }

// Empty method body
void DoNothing() { }

// Empty loop body using semicolon
while (SomeCondition()) ;  // Caution: easy to miss the semicolon!

// Better readable empty loop
while (SomeCondition()) { /* intentionally empty */ }

Q50. What is the _ discard in C# and how is it similar to pass?

Answer: The discard _ is used to intentionally ignore values — conceptually similar to pass in that it explicitly says “I don’t care about this.”

// Ignore out parameter
int.TryParse("abc", out _);

// Ignore tuple element
var (name, _) = GetNameAndAge();

// Ignore task result
_ = Task.Run(() => DoSomething());

7. Mixed / Tricky / Commonly Ignored Questions

Q51. What is the output of this code?

for (int i = 0; i < 3; i++)
{
    if (i == 1) continue;
    Console.Write(i + " ");
}

Answer: 0 2 — continue skips i=1, but i=2 is still printed.

Q52. What is the output?

int i = 0;
do
{
    Console.Write(i + " ");
    i++;
} while (i < 0);

Answer: 0 — do-while executes body once even though condition is false from the start.

Q53. What is the output?

for (int i = 0; i < 5; i++)
{
    switch (i)
    {
        case 3: break;
    }
    Console.Write(i + " ");
}

Answer: 0 1 2 3 4 — break exits the switch, not the for loop. All values are printed.

Q54. Can you have a return inside a loop? What happens?

Answer: Yes. return exits the entire method immediately, regardless of how many loops wrap it.

int FindFirst(int[] arr, int target)
{
    foreach (int n in arr)
        if (n == target) return n;  // Exits method here
    return -1;
}

Q55. What is the difference between break in a loop and return in a method that contains a loop?

Answer:

  • break exits only the innermost loop; the rest of the method continues.
  • return exits the entire method immediately.

Q56. What happens when goto is used to jump over a variable declaration?

Answer: Compile-time error. You cannot jump over the declaration of a local variable that is in scope at the target label.

goto Skip;
int x = 10;   // Jumped over — compile error
Skip:
Console.WriteLine(x);  // x might be uninitialized

Q57. What is an infinite foreach? Is it possible?

Answer: Yes, with a custom infinite enumerator.

IEnumerable<int> InfiniteCounter()
{
    int i = 0;
    while (true) yield return i++;
}

foreach (int n in InfiniteCounter())
{
    Console.WriteLine(n);
    if (n >= 10) break;  // Must break manually
}

Q58. Can you use var in a foreach? Is there any gotcha?

Answer: Yes. var infers the element type. Gotcha: if the collection is ArrayList (non-generic), var infers object, requiring a cast.

var list = new List<string> { "a", "b" };
foreach (var item in list)  // item is string
    Console.WriteLine(item.ToUpper());

var arrayList = new ArrayList { 1, "two" };
foreach (var item in arrayList)  // item is object!
    Console.WriteLine(item);

Q59. What does for (;;) mean?

Answer: It’s an infinite loop. All three parts of the for are optional; omitting the condition defaults to true. Equivalent to while (true).

Q60. Can a switch statement have no cases at all?

Answer: Yes, it’s syntactically valid but useless.

switch (x) { }  // Valid, does nothing

Q61. What is the scope of a variable declared in a switch case?

Answer: In C#, all cases share the same scope within a switch block. You must use {} to create a separate scope per case if variables with the same name are needed in multiple cases.

switch (x)
{
    case 1:
    {
        int temp = 10;  // Scoped to this block
        break;
    }
    case 2:
    {
        int temp = 20;  // No conflict — different block
        break;
    }
}

Q62. Is foreach on a null collection a compile error or runtime error?

Answer: Runtime error — NullReferenceException is thrown when foreach calls GetEnumerator() on null.

List<int> list = null;
foreach (var n in list)  // NullReferenceException at runtime!
    Console.WriteLine(n);

// Safe version
foreach (var n in list ?? Enumerable.Empty<int>())
    Console.WriteLine(n);

Q63. Can you await inside a switch expression?

Answer: Yes, from C# 8+ with async methods.

string result = await (input switch
{
    "a" => FetchAsync("Alpha"),
    "b" => FetchAsync("Beta"),
    _ => Task.FromResult("Unknown")
});

8. Advanced & Edge Cases

Q64. What is the difference between IEnumerable<T> and IEnumerator<T> and how do they relate to foreach?

Answer:

  • IEnumerable<T> — has GetEnumerator() method; represents a sequence that can be iterated.
  • IEnumerator<T> — has MoveNext(), Current, Reset(); represents the iteration state.

foreach calls GetEnumerator() on the collection, then uses the returned IEnumerator<T> to walk through elements.

// Equivalent to what foreach generates:
var enumerator = collection.GetEnumerator();
try
{
    while (enumerator.MoveNext())
    {
        var item = enumerator.Current;
        // loop body
    }
}
finally
{
    (enumerator as IDisposable)?.Dispose();
}

Q65. What happens if an exception is thrown inside a foreach? Is Dispose() called on the enumerator?

Answer: Yes. The compiler generates a try-finally block around foreach. The finally block calls Dispose() on the enumerator, even if an exception occurs. This is important for enumerators over resources like file streams.

Q66. What is the difference between while(true) with break vs. a proper loop condition for a game loop?

Answer: Both work, but while(condition) is cleaner and more maintainable. while(true) with break is useful when the exit condition is complex or determined mid-loop.

// Clear intent
while (!gameOver)
    Update();

// More complex mid-loop decision
while (true)
{
    var input = GetInput();
    if (input == "quit") break;
    ProcessInput(input);
}

Q67. Explain how switch on types (type pattern matching) works in C# 7+.

Answer:

void Describe(object obj)
{
    switch (obj)
    {
        case int i:
            Console.WriteLine($"Int: {i}");
            break;
        case string s when s.Length > 5:
            Console.WriteLine($"Long string: {s}");
            break;
        case null:
            Console.WriteLine("Null");
            break;
        default:
            Console.WriteLine("Unknown");
            break;
    }
}

Order matters — more specific cases should come before general ones.

Q68. Can the iterator variable in a for loop be a double or float?

Answer: Yes, but avoid it due to floating-point precision issues.

// Risky — floating point imprecision may cause unexpected iterations
for (double d = 0.0; d != 1.0; d += 0.1)
    Console.WriteLine(d);  // May loop forever or skip 1.0!

// Safe alternative
for (int i = 0; i <= 10; i++)
    Console.WriteLine(i / 10.0);

Q69. What is the checked and unchecked keyword’s interaction with loops?

Answer: checked blocks throw OverflowException on integer overflow; unchecked (default) wraps around silently.

checked
{
    int x = int.MaxValue;
    x++;  // OverflowException!
}

// In a loop, this can be subtle:
for (int i = int.MaxValue - 2; i <= int.MaxValue; i++)
    Console.WriteLine(i);  // Infinite loop in unchecked mode — wraps to int.MinValue

Q70. How does goto interact with using blocks and deterministic disposal?

Answer: If you goto out of a using block, the Dispose() method is still called because the compiler generates a try-finally. However, goto into a using block from outside is a compile error.

using (var conn = new SqlConnection(cs))
{
    conn.Open();
    if (errorCondition) goto Cleanup;  // Dispose is still called
    // ... more code
}
Cleanup:
    Console.WriteLine("Done");
