DAPPER ORM

Basic Questions

Q1: What is Dapper and why would you use it?

  • Lightweight ORM built on top of ADO.NET
  • Focuses on speed and efficiency
  • Minimal overhead compared to Entity Framework
  • Used for high-performance data access scenarios
  • Often called “king of micro ORMs”

Q2: How do you perform a basic query with Dapper?

using (IDbConnection db = new SqlConnection(connectionString))
{
    var users = db.Query<User>("SELECT * FROM Users WHERE Active = 1");
}

Q3: What’s the difference between Query and QuerySingle in Dapper?

  • Query<T>: Returns IEnumerable<T>, works with multiple rows
  • QuerySingle<T>: Returns single T, throws if 0 or multiple rows found
  • QueryFirstOrDefault<T>: Returns first row or default value if empty

Q4: How do you pass parameters to a Dapper query?

var user = db.Query<User>(
    "SELECT * FROM Users WHERE Id = @Id", 
    new { Id = userId }
).FirstOrDefault();

Q5: Can you explain Query vs Execute in Dapper?

  • Query<T>: Retrieves data, returns IEnumerable
  • Execute: Performs non-query operations (INSERT, UPDATE, DELETE)
  • Returns number of rows affected

Intermediate Questions

Q6: What is Dapper’s GridReader and when would you use it?

  • Used for executing multiple queries in a single database roundtrip
  • Returns multiple result sets from one command
  • Improves performance by reducing database calls
using (var multi = db.QueryMultiple(
    "SELECT * FROM Users; SELECT * FROM Roles"))
{
    var users = multi.Read<User>();
    var roles = multi.Read<Role>();
}

Q7: How do you handle NULL values in Dapper mapping?

  • Dapper automatically maps NULL database values to C# null/default values
  • For value types, consider using nullable types (int?, DateTime?)
  • Custom mapping can be done with handlers

Q8: Explain Dapper’s parameter handling and SQL injection prevention.

  • Uses parameterized queries by default
  • Parameters passed as anonymous objects are converted to SQL parameters
  • Prevents SQL injection attacks
  • Example: new { Id = userId } becomes @Id parameter

Q9: How do you map database columns to different C# property names in Dapper?

public class User
{
    public int Id { get; set; }
    [Column("UserName")]
    public string Name { get; set; }
}

Q10: What’s the performance advantage of Dapper over Entity Framework?

  • Less overhead - closer to raw ADO.NET
  • No change tracking overhead
  • Faster for read-heavy scenarios
  • Better for bulk operations
  • Can use custom SQL for complex queries

Q12: Explain how you would handle transactions in Dapper.

Q13: How do you implement caching strategies with Dapper?

  • Query results are not cached by default (unlike Entity Framework)
  • Implement manual caching using MemoryCache or DistributedCache
  • Use cache-aside pattern
  • Be mindful of cache invalidation

Q14: What’s the difference between List and GridReader results in Dapper?

  • Query<T> returns IEnumerable (deferred execution)
  • QueryMultiple returns GridReader for multiple result sets
  • GridReader must be disposed properly
  • GridReader reader is forward-only

ENTITY FRAMEWORK

Basic Questions

Q21: What is Entity Framework and its advantages?

  • ORM (Object-Relational Mapping) framework
  • Abstracts database operations
  • Supports LINQ queries
  • Automatic change tracking
  • Migration support
  • Reduced boilerplate code

Q22: Explain the difference between EF Core and EF6.

  • EF Core: Newer, lightweight, cross-platform
  • EF6: Older, full .NET Framework only
  • EF Core has breaking changes from EF6
  • EF Core is recommended for new projects

Q23: What are DbContext and DbSet?

  • DbContext: Represents session with database, manages entity instances
  • DbSet<T>: Represents collection of entities in the database
  • DbContext tracks changes to entities
public class ApplicationDbContext : DbContext
{

    public DbSet<Role> Roles { get; set; }
}

Q25: What’s the difference between SaveChanges() and SaveChangesAsync()?

  • SaveChanges(): Synchronous, blocks thread
  • SaveChangesAsync(): Asynchronous, non-blocking
  • Both persist changes to database

Intermediate Questions

Q26: Explain lazy loading, eager loading, and explicit loading in EF Core.

Lazy Loading:

var user = _context.Users.First(); // User loaded
var roles = user.Roles; // Roles loaded on access

Eager Loading:

var user = _context.Users
    .Include(u => u.Roles)
    .First();

Explicit Loading:

var user = _context.Users.First();
_context.Entry(user).Collection(u => u.Roles).Load();

Q27: What is the difference between Find and FirstOrDefault?

  • Find: Looks in change tracker first, then database (faster for identity lookup)
  • FirstOrDefault: Always queries database
  • Find works only by primary key
var user1 = _context.Users.Find(1); // Checks change tracker first
var user2 = _context.Users.FirstOrDefault(u => u.Id == 1); // Always queries

Q29: Explain change tracking in Entity Framework.

  • Change states: Added, Modified, Deleted, Unchanged, Detached

Q32: Explain the N+1 problem and how to solve it.

// N+1 Problem: 1 query for users + N queries for roles

{
    var roles = user.Roles; // Additional query for each user
}

// Solution 1: Eager loading

    .Include(u => u.Roles)

// Solution 2: Batch loading
var users = _context.Users.ToList();
_context.Entry(users).Collection(u => u.Roles).Load();

Q46: What is JWT and what are its main components?

  • JSON Web Token: Stateless authentication mechanism
  • Components: Header.Payload.Signature (3 base64 parts)
  • Header: Token type and hashing algorithm
  • Payload: Claims/data
  • Signature: Verification signature

Q47: What’s the difference between authentication and authorization?

  • Authentication: Verifying user identity (WHO you are)
  • Authorization: Verifying permissions (WHAT you can do)
  • JWT handles both through claims

Q48: How do you create a JWT in C#?

var tokenHandler = new JwtSecurityTokenHandler();
var key = Encoding.ASCII.GetBytes(secretKey);

var tokenDescriptor = new SecurityTokenDescriptor
{
    Subject = new ClaimsIdentity(new[]
    {
        new Claim(ClaimTypes.NameIdentifier, userId.ToString()),
        new Claim(ClaimTypes.Name, userName)
    }),
    Expires = DateTime.UtcNow.AddHours(1),
    SigningCredentials = new SigningCredentials(
        new SymmetricSecurityKey(key), 
        SecurityAlgorithms.HmacSha256Signature)
};

var token = tokenHandler.CreateToken(tokenDescriptor);
var tokenString = tokenHandler.WriteToken(token);

Q49: How do you validate a JWT in C#?

var tokenHandler = new JwtSecurityTokenHandler();
var key = Encoding.ASCII.GetBytes(secretKey);

try
{
    tokenHandler.ValidateToken(token, new TokenValidationParameters
    {
        ValidateIssuerSigningKey = true,
        IssuerSigningKey = new SymmetricSecurityKey(key),
        ValidateIssuer = false,
        ValidateAudience = false,
        ClockSkew = TimeSpan.Zero
    }, out SecurityToken validatedToken);
    
    var jwtToken = (JwtSecurityToken)validatedToken;
    return jwtToken;
}
catch
{
    return null;
}

Q50: What are JWT claims and what types are available?

  • Claims: Key-value pairs in payload containing user information
  • Standard claims: sub (subject), iss (issuer), aud (audience), exp (expiration)
  • Custom claims: Application-specific data
new Claim(ClaimTypes.NameIdentifier, userId),
new Claim(ClaimTypes.Role, "Admin"),
new Claim("CustomClaim", "CustomValue")

Q53: What’s the difference between symmetric and asymmetric signing?

  • Symmetric: Same key for signing and verifying (HS256 - HMAC)
  • Asymmetric: Private key for signing, public key for verifying (RS256 - RSA)
  • Asymmetric better for microservices/distributed systems
// Symmetric (HS256)
new SigningCredentials(new SymmetricSecurityKey(key), 
    SecurityAlgorithms.HmacSha256Signature)

// Asymmetric (RS256)

    SecurityAlgorithms.RsaSha256Signature)

Q56: How do you implement token revocation/blacklisting?

// Store revoked tokens in cache or database
public class TokenBlacklistService
{
    private readonly IDistributedCache _cache;
    
    public async Task RevokeTokenAsync(string token, TimeSpan expiration)
    {
        await _cache.SetStringAsync($"revoked_token_{token}", "1",

Q57: How do you handle JWT expiration and renewal?

[HttpPost("refresh")]
public IActionResult RefreshToken([FromBody] RefreshTokenRequest request)
{
    // Validate refresh token
    var principal = GetPrincipalFromExpiredToken(request.AccessToken);
    
    var user = _context.Users.FirstOrDefault(u => u.RefreshToken == request.RefreshToken);
    
    if (user == null || user.RefreshTokenExpiryTime <= DateTime.UtcNow)
    {
        return BadRequest("Invalid refresh token");
    }
    
    var newAccessToken = GenerateAccessToken(user, 15);
    return Ok(new { token = newAccessToken });
}

private ClaimsPrincipal GetPrincipalFromExpiredToken(string token)
{
    var tokenHandler = new JwtSecurityTokenHandler();
    var key = Encoding.ASCII.GetBytes(secretKey);
    
    try
    {
        var principal = tokenHandler.ValidateToken(token, new TokenValidationParameters
        {
            ValidateIssuerSigningKey = true,
            IssuerSigningKey = new SymmetricSecurityKey(key),
            ValidateIssuer = false,
            ValidateAudience = false,
            ValidateLifetime = false // Don't validate expiration
        }, out SecurityToken validatedToken);
        
        return principal;
    }
    catch
    {
        return null;
    }
}

Q58: How do you implement custom claim-based authorization?

public class ClaimRequirement : IAuthorizationRequirement
{
    public string ClaimType { get; set; }
    public string ClaimValue { get; set; }
}

public class ClaimHandler : AuthorizationHandler<ClaimRequirement>
{
    protected override Task HandleRequirementAsync(AuthorizationHandlerContext context, 
        ClaimRequirement requirement)
    {
        if (context.User.HasClaim(requirement.ClaimType, requirement.ClaimValue))
        {
            context.Succeed(requirement);
        }
        
        return Task.CompletedTask;
    }
}

// Usage

{
    options.AddPolicy("CanEditUsers", policy =>
        policy.Requirements.Add(new ClaimRequirement { 
            ClaimType = "Permission", 
            ClaimValue = "EditUsers" 
        }));
});

IENUMERABLE vs IQUERYABLE

Basic Questions

Q66: What is the difference between IEnumerable and IQueryable?

Feature IEnumerable IQueryable
Namespace System.Collections System.Linq
Execution In-memory (LINQ to Objects) Provider-based (SQL, REST, etc.)
Query Timing Deferred (executes when enumerated) Deferred (executes when enumerated)
Filtering Location In-memory (after retrieval) At source (before retrieval)
Performance Less efficient for large datasets More efficient
Providers Only LINQ to Objects Multiple providers

Q67: When would you use IEnumerable vs IQueryable?

  • IEnumerable: For in-memory collections
  • IQueryable: For database/remote data sources
  • IEnumerable: When filtering small datasets
  • IQueryable: When filtering large datasets

Q68: How does deferred execution work with IEnumerable?

IEnumerable<int> numbers = new[] { 1, 2, 3, 4, 5 };

foreach (var num in query) // Executed here
{
    Console.WriteLine(num); // 3, 4, 5
}

IQueryable<User> query = _context.Users.Where(u => u.IsActive);

Q70: What is Expression and how does IQueryable use it?

  • Expression: Represents code as data structure
  • IQueryable uses Expression trees instead of delegates
  • Allows query translation to provider language (SQL)
// IEnumerable: Delegate (Func)
Func<User, bool> predicate1 = u => u.IsActive;

// IQueryable: Expression tree
Expression<Func<User, bool>> predicate2 = u => u.IsActive;

Intermediate Questions

Q71: Explain the performance difference between these two approaches:

// Approach 1: IEnumerable (Less efficient)
var users = _context.Users.ToList(); // Loads all users
var activeUsers = users.Where(u => u.IsActive).ToList(); // Filters in memory

// Approach 2: IQueryable (More efficient)
var activeUsers = _context.Users
    .Where(u => u.IsActive)
    .ToList(); // Filters in database, loads only active users
  • Approach 1: Transfers all data, filters in-memory
  • Approach 2: Filters at database, transfers only needed data

Q72: When does IQueryable actually execute the query?

var list = query.ToList(); // Executed: SELECT * WHERE IsActive ORDER BY Name
  • Materialization triggers execution: .ToList(), .Count(), .First(), etc.

Q76: How do you dynamically build IQueryable expressions?

public IQueryable<User> BuildDynamicQuery(
    IQueryable<User> query, 
    string searchTerm, 
    DateTime? fromDate)
{
    if (!string.IsNullOrEmpty(searchTerm))
    {
        query = query.Where(u => u.Name.Contains(searchTerm));
    }
    
    if (fromDate.HasValue)
    {
        query = query.Where(u => u.CreatedDate >= fromDate);
    }
    
    return query;

Q77: Explain Expression tree composition and predicate builders.

public static class PredicateBuilder
{
    public static Expression<Func<T, bool>> True<T>() 
        => param => true;

    public static Expression<Func<T, bool>> Combine<T>(
        Expression<Func<T, bool>> first, 
        Expression<Func<T, bool>> second,
        Func<Expression, Expression, Expression> combiner)
    {
        var invokedSecond = Expression.Invoke(second, first.Parameters.Cast<Expression>());
        return Expression.Lambda<Func<T, bool>>(
            combiner(first.Body, invokedSecond),
            first.Parameters);
    }

    public static Expression<Func<T, bool>> And<T>(
        Expression<Func<T, bool>> first,
        Expression<Func<T, bool>> second)
        => Combine(first, second, Expression.And);

    public static Expression<Func<T, bool>> Or<T>(
        Expression<Func<T, bool>> first,
        Expression<Func<T, bool>> second)
        => Combine(first, second, Expression.Or);
}

// Usage
var predicate = PredicateBuilder.True<User>()
    .And(u => u.IsActive)
    .And(u => u.CreatedDate >= DateTime.Now.AddDays(-30));

var users = _context.Users.Where(predicate).ToList();

BOXING vs UNBOXING

Basic Questions

Q106: What is boxing?

  • Converting value type to reference type
  • Creates heap allocation
  • Wraps value in object
  • Value type → object
int intValue = 10; // Value type on stack
object boxedValue = intValue; // Boxing: copied to heap as object

Q107: What is unboxing?

  • Converting boxed object back to value type
  • Must match original type
  • Throws InvalidCastException if type mismatch
  • object → value type
object boxedValue = 10;
int unboxedValue = (int)boxedValue; // Unboxing
// unboxedValue = 10

Q108: What’s the performance impact of boxing?

  • Boxing: Memory allocation on heap
  • Unboxing: Copy from heap to stack
  • Creates garbage collection pressure
  • Should be minimized in performance-critical code

Q109: When does boxing happen implicitly?

int value = 5;

// Implicit boxing
object obj = value; // Boxing happens
Console.WriteLine(value); // ToString() might box

// Boxing in collections
ArrayList list = new ArrayList();
list.Add(5); // Implicit boxing

Q110: How do you avoid boxing?

// Avoid: Boxing with ArrayList
ArrayList list = new ArrayList();
list.Add(5); // Boxes int

// Prefer: Generics prevent boxing
List<int> list = new List<int>();
list.Add(5); // No boxing

  • Returns single value from first column, first row
  • Returns object (can be null)
  • Used for scalar queries: COUNT, SUM, MAX, etc.
  • Closes connection after execution

Q134: How do you implement a generic ExecuteScalar helper?

public T ExecuteScalar<T>(string query)
{
    using (SqlConnection connection = new SqlConnection(connectionString))
    {
        SqlCommand command = new SqlCommand(query, connection);
        connection.Open();
        
        object result = command.ExecuteScalar();
        
        if (result == null || result is DBNull)
        {
            return default(T);
        }
        
        return (T)Convert.ChangeType(result, typeof(T));
    }
}
