OOPS

Basic Level

  1. What is Object-Oriented Programming (OOP)?
Answer: A programming paradigm based on objects and classes that
organize code into reusable, self-contained units.
  1. What are the four pillars of OOP?
Answer: Encapsulation, Inheritance, Polymorphism, and Abstraction.
  1. What is a class and an object?
Answer: A class is a blueprint, an object is an instance of that blueprint.
  1. What is encapsulation?
Answer: Bundling data and methods together and hiding internal details
using access modifiers (public, private, protected).
  1. What are access modifiers in C#?
    Answer: public, private, protected, internal, protected internal, private
    protected.
  2. What is the difference between a reference type and a value type?
Answer: Value types (struct, int, double) are stored on the stack; reference
types (class, object) are stored on the heap.
  1. What is inheritance?
Answer: A mechanism where a derived class inherits properties and
methods from a base class.
  1. Can you inherit from multiple classes in C#?
Answer: No, C# does not support multiple inheritance from classes. You can
implement multiple interfaces though.
  1. What is polymorphism?
Answer: The ability of objects to take multiple forms. Two types: compile-
time (method overloading) and runtime (method overriding).
  1. What is abstraction?
Answer: Hiding complex implementation details and showing only the
necessary features.

Intermediate Level

  1. What is the difference between abstract classes and interfaces?
Answer:
Abstract classes can have concrete methods, fields; interfaces cannot
(before C# 8.0)
Abstract classes can have access modifiers; interface members are
public by default
A class can implement multiple interfaces but inherit from only one
abstract class
Abstract classes are “IS-A” relationships; interfaces are “CAN-DO”
relationships
  1. Can you instantiate an abstract class?
Answer: No, abstract classes cannot be instantiated directly. You must create
a derived class.
  1. What are virtual and override keywords?
Answer: virtual allows a method to be overridden in derived classes;
override explicitly overrides a virtual method.
  1. What is method hiding (using the new keyword)?
Answer: It’s when a derived class defines a method with the same name as a
base class method without using override. It hides the base method
completely.
  1. What is the difference between method overloading and method overriding?
Answer:
Overloading: Multiple methods with the same name but different
parameters (compile-time polymorphism)
Overriding: Child class provides specific implementation of parent’s
virtual method (runtime polymorphism)
  1. Can you override a static method?
Answer: No, static methods cannot be overridden. They can only be hidden
using the new keyword.
  1. What is a constructor and a destructor?
Answer: Constructor initializes an object; destructor cleans up resources. C#
uses finalizers (~ClassName) not destructors.
  1. Can a constructor be private?
Answer: Yes, private constructors are used in singleton patterns and factory
patterns to control object creation.
  1. What is constructor chaining?
Answer: Calling one constructor from another using : this() or : base().
  1. What is an immutable object?
Answer: An object whose state cannot be changed after creation. Use
readonly keyword or properties with only getters.

Advanced Level

  1. What is the difference between struct and class?
Answer:
Struct is a value type; class is a reference type
Struct is stored on stack; class on heap
Struct cannot inherit from other structs/classes; class can inherit
Struct members cannot be initialized inline; class members can
Struct is copied by value; class by reference
  1. When should you use a struct over a class?
Answer: For small, immutable data structures; when you want stack
allocation; for performance-critical code; when you don’t need inheritance.
  1. What is the diamond problem in inheritance?
Answer: When a class inherits from two classes that have a common
ancestor, it’s unclear which ancestor’s methods to use. C# avoids this using
interfaces.
  1. What is covariance and contravariance?
Answer:
Covariance: Allows a derived type where a base type is expected
(return types)
Contravariance: Allows a base type where a derived type is expected
(parameter types)
  1. What are sealed classes?
Answer: Classes that cannot be inherited from. Used to prevent further
derivation.
  1. What is the difference between explicit and implicit interface
    implementation?
Answer:
Implicit: Implement interface members as public members
Explicit: Implement using InterfaceName.MemberName, making them
private
Explicit implementation is useful when interfaces have conflicting
member names
  1. What is a nested class?
Answer: A class defined inside another class. Can access private members of
the outer class if non-static.
  1. What is the purpose of the base keyword?
    Answer: To access base class members (methods, properties, constructors)
    from a derived class.
  2. How does C# handle multiple inheritance through interfaces?
Answer: A class can implement multiple interfaces, effectively achieving
multiple inheritance of type/contract.
  1. What is the Object class in C#?
Answer: The base class of all classes in C#. Key methods: GetType(),
ToString(), GetHashCode(), Equals().

Static Classes & Keywords

Basic Level

  1. What is a static class?
Answer: A class that cannot be instantiated. All members must be static.
Used for utility/helper methods.
  1. What is the static keyword?
Answer: Makes a member (variable, method, class) belong to the type itself,
not to instances.
  1. What is the difference between static and non-static members?
Answer:
Static members are shared across all instances
Non-static members are unique to each instance
  1. Can you inherit from a static class?
Answer: No, static classes are sealed implicitly and cannot be inherited.
  1. Can a static class have instance members?
Answer: No, all members in a static class must be static.
  1. What is a static variable?
Answer: A variable shared across all instances of a class. Initialized once and
persists for the application lifetime.
  1. What is a static method?
Answer: A method that belongs to the class, not to instances. Called using
ClassName.MethodName().
  1. What is a static constructor?
Answer: A parameterless constructor that initializes static members. Called
automatically before the first instance is created or a static member is
accessed.
  1. When is a static constructor called?
Answer: Before the first instance is created or before a static member is
accessed, whichever comes first.
  1. Can a static constructor throw an exception?
Answer: Yes, but it will prevent the class from being used and throw a
TypeInitializationException.

Intermediate Level

  1. What is a static property?
Answer: A property that belongs to the class itself. Accessed via
ClassName.PropertyName.
  1. What is the difference between a static class and a class with all static
    members?
Answer:
Static class: Cannot be instantiated, all members must be static
Regular class with static members: Can be instantiated, mix of static
and instance members
  1. Can you use ‘this’ keyword in a static method?
Answer: No, this refers to the current instance, which doesn’t exist in static
context.
  1. What is a static import (using static)?
Answer: Allows you to use static members without the class name: using
static ClassName;
  1. What happens if you try to access an instance member from a static method?
    Answer: Compiler error - you cannot access instance members from a static
    context.
  2. Are static members initialized before instance members?
Answer: Yes, static members are initialized first.
  1. Can a static method call a non-static method?
Answer: No, unless it creates an instance first.
  1. What is a static field initialization order?
Answer: Static fields are initialized in the order they’re declared before the
static constructor runs.
  1. What is the purpose of static readonly?
Answer: To create a constant that can be initialized at runtime but cannot be
changed after assignment.
  1. What is the difference between const and static readonly?
Answer:
const: Compile-time constant, inlined, cannot be changed
static readonly: Runtime constant, not inlined, can be initialized in
constructor

Advanced Level

  1. How do static classes relate to dependency injection?
Answer: Static classes are generally avoided in DI because they’re hard to
mock and test, creating tight coupling.
  1. What is the issue with static methods in terms of testability?
Answer: Static methods cannot be mocked, making unit testing difficult. DI is
preferred for testable code.
  1. Can you use async methods in a static context?
Answer: Yes, but you need to be careful with static state and concurrent
access.
  1. What is a static factory method?
    Answer: A static method that creates and returns instances of a class.
    Provides more flexibility than constructors.
  2. What are the pitfalls of using static variables in multithreaded applications?
Answer: Race conditions, need for synchronization, state sharing issues. Use
thread-local storage or locks if necessary.
  1. How do you ensure thread safety with static variables?
Answer: Use locks (lock statement), volatile keyword, Interlocked class,
or ThreadLocal<T>.
  1. What is a static factory pattern?
Answer: A design pattern using static methods to control object creation
instead of constructors.
  1. Can you override a static method?
Answer: No, you can only hide it using the new keyword.
  1. What is the difference between static and sealed?
Answer: static makes all members belong to the type; sealed prevents
inheritance.
  1. What is the memory overhead of static variables?
Answer: Static variables are stored in the heap and persist for the application
lifetime, increasing memory usage.

async/await

Basic Level

  1. What is asynchronous programming?
Answer: Programming that doesn’t block the calling thread. The operation
runs independently, and the result is obtained when ready.
  1. What is the async keyword?
Answer: A modifier that indicates a method is asynchronous and can use
await.
  1. What is the await keyword?
Answer: Pauses execution until an awaitable Task completes, then resumes
with the result.
  1. What is a Task in C#?
Answer: Represents an asynchronous operation that may or may not return
a value.
  1. What is the difference between Task and Task?
Answer: Task represents an operation without a return value; Task
represents an operation that returns a value of type T.
  1. What is the naming convention for async methods?
Answer: Async methods should be named with an “Async” suffix (e.g.,
GetDataAsync).
  1. Can an async method return void?
Answer: Technically yes, but it’s not recommended. Use Task or Task<T>
instead. Only use async void for event handlers.
  1. What happens when you await a completed Task?
Answer: Execution continues immediately without blocking if the Task is
already completed.
  1. Can you use await outside an async method?
Answer: No, you must be in an async method. However, C# 11+ allows top-
level await in some contexts.
  1. What is the difference between blocking and non-blocking calls?
Answer:
Blocking: Halts execution until the operation completes
Non-blocking: Returns control immediately; the operation continues in
the background

Intermediate Level

  1. What is ConfigureAwait(false)?
Answer: Tells the task not to capture the current synchronization context,
avoiding deadlocks and improving performance.
  1. When should you use ConfigureAwait(false)?
Answer: In library code to avoid forcing a specific synchronization context on
the caller.
  1. What is a synchronization context?
Answer: An abstraction that ensures continuations run on the same thread.
Important in UI frameworks like WinForms.
  1. What is the difference between Task.Run and Task.Factory.StartNew?
Answer:
Task.Run: Queues work to the thread pool
Task.Factory.StartNew: More control over task scheduling and options
  1. What is async all the way?
Answer: An architectural pattern where async is used consistently from the
top-level entry point down to I/O operations.
  1. What happens if you don’t await a Task?
Answer: The Task runs in the background; you won’t get the result. May
cause “fire and forget” issues.
  1. How do you handle exceptions in async methods?
Answer: Use try-catch blocks around await statements. The exception
propagates through the Task.
  1. What is Task.WhenAll?
Answer: Waits for multiple tasks to complete. Returns a task that completes
when all tasks are done.
  1. What is Task.WhenAny?
Answer: Returns a task that completes when any of the awaited tasks
completes.
  1. What is Task.Delay?
Answer: An asynchronous equivalent of Thread.Sleep that doesn’t block the
thread.
  1. What is a deadlock in async code?
Answer: When multiple tasks wait for each other to complete, causing
indefinite blocking.
  1. How can you prevent deadlocks in async code?
Answer: Use ConfigureAwait(false), avoid mixing sync and async, use async
all the way.
  1. What is the difference between async void and async Task?
Answer:
async void: Fire and forget, no way to track completion
async Task: Can be awaited, exceptions propagate properly
  1. What is ValueTask?
Answer: A lightweight struct that represents an async operation. More
efficient than Task for operations that often complete synchronously.
  1. When should you use ValueTask instead of Task?
Answer: For performance-critical code where allocations matter and
operations often complete synchronously.

Advanced Level

  1. What is async state machine?
Answer: The compiler-generated state machine that implements the
async/await logic. It manages state transitions and continuations.
  1. How does the compiler transform async/await code?
Answer: Converts the async method into a state machine with different
states for each await point.
  1. What is a synchronization context in detail?
Answer: An abstraction (SynchronizationContext) that ensures continuations
run on a specific thread/context (e.g., UI thread).
  1. What is IAsyncEnumerable?
Answer: Represents an asynchronous enumerable collection. Used with
await foreach for streaming async data.
  1. What is async streams?
Answer: Using async IAsyncEnumerable<T> with yield return to produce
values asynchronously.
  1. How do you iterate over an async enumerable?
Answer: Using await foreach (var item in asyncEnumerable).
  1. What is the difference between Task-based asynchrony and async/await?
Answer: async/await is syntactic sugar built on top of Task-based
asynchrony, making it more readable.
  1. What happens if a Task throws an exception?
Answer: The exception is captured in the Task. When you await, the
exception is thrown at the await point.
  1. What is UnobservedTaskException?
Answer: An exception thrown by a Task that was never awaited or checked. It
may cause the application to crash.
  1. How do you prevent UnobservedTaskException?
Answer: Always await or attach handlers to Tasks using ContinueWith or
exception handling.
  1. What is async local storage?
Answer: Data stored per async call, not per thread. Use AsyncLocal for this
purpose.
  1. What is the difference between Thread.Sleep and Task.Delay?
Answer:
Thread.Sleep: Blocks the thread
Task.Delay: Returns a task that completes after delay without blocking
  1. Can you await a regular synchronous method?
Answer: No, the method must return Task or Task.
  1. What is a TaskScheduler?
Answer: Manages how tasks are executed. Default is the thread pool
scheduler.
  1. What are the performance implications of async/await?
Answer: Minimal overhead due to compiler optimization. But excessive
allocations and synchronization contexts can impact performance.

Dependency Injection

Basic Level

  1. What is Dependency Injection (DI)?
Answer: A design pattern where a class receives its dependencies from
external sources rather than creating them itself.
  1. What is the difference between Dependency Injection and Service Locator?
Answer:
DI: Dependencies are injected into the class (preferred, explicit)
Service Locator: The class asks a service locator for its dependencies
(implicit, anti-pattern)
  1. What are the types of Dependency Injection?
Answer: Constructor Injection, Property Injection, Method Injection, and
Interface Injection.
  1. What is Constructor Injection?
Answer: Dependencies are passed through the class constructor. Most
common and recommended approach.
  1. What is Property Injection?
Answer: Dependencies are set through public properties after object
creation.
  1. What is Method Injection?
Answer: Dependencies are passed as parameters to methods that use them.
  1. What is the IServiceProvider interface?
Answer: A built-in interface for retrieving services from the DI container.
  1. What is a DI Container?
Answer: A framework that manages object creation and dependency
resolution (e.g., Microsoft.Extensions.DependencyInjection).
  1. What is the purpose of the IServiceCollection interface?
Answer: Used to register services with the DI container during configuration.
  1. How do you register services in .NET Core?
Answer: Using IServiceCollection methods like AddScoped, AddSingleton,
AddTransient.

Intermediate Level

  1. What is the difference between Scoped, Singleton, and Transient lifetimes?
Answer:
Singleton: One instance for the application lifetime
Scoped: One instance per request/scope
Transient: New instance every time it’s requested
  1. How do you resolve a service from the DI container?
Answer: Using IServiceProvider.GetService() or GetRequiredService().
  1. What is constructor injection vs property injection?
Answer:
Constructor: Dependencies are required, immutable, explicit
Property: Dependencies are optional, mutable, implicit
  1. What is the Factory pattern in DI?
Answer: Using a factory function to create instances, providing more control
over object creation.
  1. How do you register a factory method with the DI container?
Answer: Using AddScoped(sp => new
MyService(sp.GetService<IDependency>())).
  1. What is auto-wiring?
Answer: The DI container automatically resolving dependencies based on
type signatures.
  1. What is circular dependency?
Answer: When two or more services depend on each other, creating a
circular reference that cannot be resolved.
  1. How do you handle circular dependencies?
Answer: Refactor to remove the circular dependency, use lazy loading, or use
a factory/service locator.
  1. How do you register an interface with a concrete type?
Answer: services.AddScoped<IRepository, Repository>();
  1. What is the difference between registering a type and registering an
    instance?
    Answer:
    Type registration: Container creates the instance
    Instance registration: A pre-created instance is registered

Advanced Level

  1. What is decorator pattern in DI?
Answer: Wrapping one implementation with another to add functionality
without modifying the original.
  1. How do you implement the decorator pattern with DI?
Answer: Register multiple implementations of the same interface, with one
decorating the other.
  1. What is the Factory pattern with DI?
Answer: Using a factory service to control object creation within the DI
container.
  1. What is Composition Root?
Answer: The application entry point where all DI configuration happens. Only
place where the container is used directly.
  1. Why should DI configuration be in the Composition Root?
Answer: To keep DI concerns separated from business logic and improve
testability.
  1. What is Service Locator anti-pattern?
Answer: Using a global service locator to resolve dependencies, hiding
dependencies and making testing difficult.
  1. Why is Service Locator considered an anti-pattern?
Answer: Hidden dependencies, harder to test, tighter coupling, unclear
object creation flow.
  1. What is the purpose of IDisposable in DI?
Answer: Services can implement IDisposable to clean up resources when the
container is disposed.
  1. How does the DI container handle IDisposable?
Answer: Scoped and Transient services are disposed when the scope ends;
Singletons are disposed when the container is disposed.
  1. What is Scope in DI?
Answer: A lifetime period during which scoped instances are reused (typically
per HTTP request in ASP.NET Core).
  1. How do you create a new scope manually?
Answer: Using serviceProvider.CreateScope() to get an IServiceScope.
  1. What is the performance impact of DI?
Answer: Minimal overhead due to compilation. DI containers are highly
optimized in .NET.
  1. How do you register conditional services in DI?
Answer: Using a factory method to return different implementations based
on conditions.
  1. What is open generic registration?
Answer: Registering generic types like IRepository<> and letting the
container resolve specific versions.
  1. How do you handle optional dependencies in DI?
Answer: Use property injection, optional constructor parameters, or check
for null after injection.
  1. What is the difference between GetService and GetRequiredService?
Answer:
GetService: Returns null if not found
GetRequiredService: Throws InvalidOperationException if not found
  1. What is keyed service registration?
Answer: Registering multiple implementations with different keys to
distinguish between them.
  1. How do you use keyed services in .NET Core?
Answer: Using AddKeyedScoped<T>(key, ...) and resolving with
GetKeyedService<T>(key).
  1. What is dependency inversion principle?
Answer: High-level modules should not depend on low-level modules; both
should depend on abstractions. DI is a way to achieve this.
  1. What is the relationship between DI and SOLID principles?
Answer: DI is a technique to implement SOLID principles, particularly
Dependency Inversion and Single Responsibility.

SOLID Principles

Basic Level

  1. What does SOLID stand for?
Answer: Single Responsibility, Open/Closed, Liskov Substitution, Interface
Segregation, Dependency Inversion.
  1. What is Single Responsibility Principle (SRP)?
Answer: A class should have only one reason to change, meaning it should
have only one responsibility.
  1. Why is SRP important?
Answer: Improves maintainability, testability, and reusability. Makes code
easier to understand and modify.
  1. What is an example of violating SRP?
Answer: A User class that handles user data, authentication, email sending,
and logging.
  1. How do you fix SRP violations?
Answer: Separate concerns into different classes, each with a single
responsibility.
  1. What is Open/Closed Principle (OCP)?
Answer: Software should be open for extension but closed for modification.
  1. How do you achieve OCP?
Answer: Use inheritance, interfaces, and abstract classes. Use design
patterns like Strategy, Decorator, Observer.
  1. What is an example of violating OCP?
Answer: Modifying existing code every time you add a new feature instead of
extending through interfaces.
  1. What is Liskov Substitution Principle (LSP)?
Answer: Derived classes should be substitutable for their base classes
without breaking the application.
  1. What is an example of violating LSP?
Answer: A Rectangle class with a Square subclass that overrides setWidth
and setHeight, breaking expected behavior.
  1. What is Interface Segregation Principle (ISP)?
Answer: Clients should not depend on interfaces they don’t use. Keep
interfaces small and focused.
  1. What is an example of violating ISP?
Answer: A large IWorker interface with methods unrelated to certain
implementations that don’t need them.
  1. What is Dependency Inversion Principle (DIP)?
Answer: High-level modules should not depend on low-level modules. Both
should depend on abstractions.
  1. How does DI relate to DIP?
Answer: Dependency Injection is a technique to implement Dependency
Inversion Principle.

Intermediate Level

  1. How does SRP improve testability?
Answer: With single responsibility, classes are easier to test because they
have fewer dependencies and concerns.
  1. What is the Template Method pattern in relation to OCP?
Answer: Defines the skeleton of an algorithm in a base class, allowing
subclasses to override specific steps without modifying the algorithm.
  1. What is the Strategy pattern in relation to OCP?
    Answer: Encapsulates algorithms in separate classes, allowing runtime
    selection without modifying the context class.
  2. How does composition over inheritance relate to SOLID?
Answer: Promotes OCP, LSP, and ISP by avoiding tight coupling and inflexible
hierarchies.
  1. What is the difference between cohesion and coupling?
Answer:
Cohesion: How closely related responsibilities are within a class (high
cohesion = good)
Coupling: How dependent classes are on each other (low coupling =
good)
  1. How do SOLID principles relate to each other?
Answer: They’re interconnected; following one often helps with others. DI is
central to achieving DIP, which supports OCP.
  1. What is the role-based interface in ISP?
Answer: Creating interfaces based on client needs/roles rather than
implementation capabilities.
  1. How do you identify SRP violations?
    Answer: Look for multiple reasons a class might change, multiple
    responsibilities, low cohesion.
  2. What is the Liskov Substitution Principle in contracts?
Answer: Derived classes must honor the contracts (preconditions,
postconditions) of their base classes.
  1. What is behavior preservation in LSP?
Answer: Ensuring derived classes maintain the expected behavior of the
base class.
  1. How do you apply ISP in a .NET application?
Answer: Define small, focused interfaces based on client requirements, not
implementation capabilities.

Advanced Level

  1. What is the relationship between SRP and cohesion?
Answer: High cohesion is achieved by following SRP; related functionality
stays together, unrelated functionality separates.
  1. How do you measure if a design follows SOLID?
Answer: Look at ease of testing, maintainability, number of changes for new
features, code reuse, and coupling levels.
  1. What is the tension between SRP and DRY (Don’t Repeat Yourself)?
Answer: Sometimes repeating code follows SRP. DRY should not force
unrelated code together.
  1. How does OCP relate to polymorphism?
Answer: Polymorphism (through interfaces/inheritance) enables OCP by
allowing extension without modification.
  1. What is the Visitor pattern in relation to OCP?
Answer: Allows adding new operations to objects without modifying their
structure, achieving OCP.
  1. What is the difference between interface-based and inheritance-based design
    in SOLID?
Answer:
Interface-based: More flexible, supports multiple implementations,
better for DIP
Inheritance-based: Tighter coupling, less flexible, but can share
implementation
  1. How does the Factory pattern support SOLID?
Answer: Separates object creation (SRP), allows easy extension (OCP), and
enables DI (DIP).
  1. What is the relationship between SOLID and design patterns?
Answer: Design patterns are solutions that help implement SOLID principles.
  1. How do you balance SOLID principles with pragmatism?
Answer: Understand the principles deeply, apply them where they add value,
avoid over-engineering for simple scenarios.
  1. What is the impact of SOLID on codebase evolution?
Answer: SOLID-adherent code is more flexible, easier to maintain, and
requires fewer changes as requirements evolve.
  1. How does Interface Segregation relate to API design?
Answer: Small, focused interfaces make APIs easier to understand and
implement correctly.
  1. What is the principle of least surprise in relation to LSP?
Answer: Derived classes should behave as users of the base class would
expect, not surprise them with unexpected behavior.
  1. How do you teach SOLID to junior developers?
Answer: Use real-world examples, show violations and fixes, emphasize
pragmatism, and enforce through code reviews.
  1. What is the cost of over-applying SOLID?
Answer: Over-engineering, excessive interfaces, unnecessary abstraction,
reduced code readability.
  1. What is the long-term benefit of SOLID in large applications?
    Answer: Reduced maintenance cost, faster feature development, better code
    quality, and easier team onboarding.

Service Lifetime

Basic Level

  1. What is Service Lifetime?
Answer: The duration for which a service instance exists and is reused in a DI
container.
  1. What are the three service lifetimes in .NET Core?
Answer: Singleton, Scoped, and Transient.
  1. What is a Singleton service?
Answer: A service created once and reused for the entire application lifetime.
  1. When should you use Singleton?
Answer: For stateless services, configuration, database connections, logging,
caching.
  1. What is a Scoped service?
Answer: A service created once per scope (typically per HTTP request in
ASP.NET Core).
  1. When should you use Scoped?
    Answer: For stateful services like Entity Framework DbContext, per-request
    data repositories.
  2. What is a Transient service?
Answer: A new instance is created every time the service is requested.
  1. When should you use Transient?
Answer: For lightweight, stateless services; objects that might have state or
side effects.
  1. What is the default lifetime when registering a service?
    Answer: There’s no default; you must specify using AddSingleton,
    AddScoped, or AddTransient.
  2. What happens if you forget to specify lifetime?
Answer: You’ll get a compilation error because the extension method is
overloaded to require explicit lifetime.

Intermediate Level

  1. What is the problem with using Scoped services in Singleton?
Answer: The Scoped instance is captured by the Singleton, and the same
Scoped instance is reused across scopes, losing Scoped benefits.
  1. How do you inject a Scoped service into a Singleton?
Answer: Use a factory pattern or service provider to resolve the Scoped
service when needed, not during Singleton construction.
  1. What is a scope in ASP.NET Core?
Answer: A lifetime period, typically one HTTP request. A new scope is created
per request.
  1. What is the performance difference between lifetimes?
Answer: Singleton is fastest (created once); Transient is slowest (created
every time); Scoped is in between.
  1. What is object pooling in relation to lifetimes?
Answer: Reusing objects instead of creating new ones. Scoped and Singleton
enable pooling.
  1. What is the memory impact of Singleton?
Answer: Singleton instances persist for the application lifetime, consuming
memory throughout the app’s life.
  1. What is the memory impact of Transient?
Answer: Many instances are created and discarded, increasing GC pressure.
  1. How do you choose between Scoped and Transient?
Answer:
Scoped: If the instance should be reused within a request
Transient: If each component needs a fresh instance
  1. What is IDisposable in the context of service lifetimes?
Answer: Services implementing IDisposable are disposed when their lifetime
ends (Scoped/Transient at scope end, Singleton at app shutdown).
  1. What happens if a Singleton implements IDisposable?
Answer: It’s disposed when the application shuts down or when the service
provider is disposed.

Advanced Level

  1. What is the captive dependency problem?
Answer: A longer-lived service (Singleton) depends on a shorter-lived service
(Scoped/Transient), causing the shorter-lived service to become a Singleton.
  1. How do you avoid captive dependencies?
Answer: Never inject Scoped/Transient into Singleton directly. Use factories
or service provider.
  1. What is lazy initialization in service lifetimes?
Answer: Creating services only when needed, not when the DI container is
built.
  1. How do you implement lazy initialization?
Answer: Use Lazy<T> wrapper or factory functions that create services on-
demand.
  1. What is IAsyncDisposable?
Answer: An interface for services that need asynchronous cleanup, similar to
IDisposable but async.
  1. How do Scoped services work in background tasks?
Answer: Background tasks don’t have a natural scope, so you must create a
scope manually using serviceProvider.CreateScope().
  1. What is the difference between AddXxx and AddXxxAsync?
Answer: These don’t differ in the DI registration itself; you manually handle
async in your service initialization.
  1. What happens if a Singleton depends on multiple Scoped services?
Answer: All those Scoped services become Singletons too (captive
dependency), defeating Scoped benefits.
  1. How do you register a factory as a service?
Answer: Using AddScoped(sp => new
MyService(sp.GetService<IDependency>())).
  1. What is service resolution performance?
Answer: The time it takes for the DI container to resolve a service. Compiled
containers (like Scrutor) optimize this.
  1. What is the difference between lifetime validation and compile-time
    verification?
Answer:
Validation: Runtime checks for captive dependencies
Compile-time: Static analysis tools detect issues before runtime
  1. How do you enable lifetime validation in .NET Core?
Answer: Using ValidateScopes = true on ServiceCollection or
ServiceProviderOptions.
  1. What is the purpose of ValidateOnBuild?
Answer: Validates service registrations when the service provider is built,
catching errors early.
  1. What is the relationship between service lifetime and request context?
Answer: In ASP.NET Core, a request creates a scope; Scoped services are
created per request and disposed after the request completes.
  1. How do you test services with different lifetimes?
Answer: Create a test service provider with the appropriate lifetimes, inject
mocks, and verify behavior.
  1. What is the impact of service lifetime on distributed systems?
    Answer: Singleton may cause issues across servers; Scoped and Transient
    are safer but require careful state management.
  2. How do you handle entity framework DBContext lifetime?
Answer: Use Scoped lifetime to ensure one context per request, avoiding
state leaks.
  1. What is the difference between Owned and Func for lifetime control?
Answer:
Owned: The dependent owns the instance lifetime
Func: The dependent can create instances on demand
  1. What is the purpose of KeyedService in service lifetimes?
Answer: Allows multiple services of the same type with different keys, each
with their own lifetime.
  1. How do you migrate from one lifetime to another?
Answer: Understand the impact, update DI registration, test thoroughly,
watch for captive dependencies.

Commonly Ignored Questions

These are questions often skipped during study but frequently

asked in interviews

  1. What is boxing and unboxing?
Answer: Boxing converts a value type to a reference type (stored on heap);
unboxing converts back to value type.
Code Example:

int x = 5 ;
object box = x; // Boxing
int unbox = (int)box; // Unboxing
  1. What is the performance impact of boxing/unboxing?
Answer: Performance overhead and memory allocation. Use generics to
avoid boxing.
  1. What is a nullable type?
Answer: A value type wrapped to allow null values using? syntax (e.g.,
int?, bool?).
  1. What is the difference between == and .Equals()?
Answer:
==: Compares references for objects, values for value types (can be
overridden)
.Equals(): Compares values (can be overridden), more reliable
  1. What is the difference between var and dynamic?
Answer:
var: Type is determined at compile-time
dynamic: Type checking is deferred to runtime
  1. What is the purpose of the GetHashCode() method?
Answer: Returns a hash value used in hash-based collections (Dictionary,
HashSet). Must be consistent with Equals().
  1. What is GetType() method?
Answer: Returns the Type object representing the runtime type of an
instance.
  1. What is reflection?
Answer: The ability to inspect and manipulate types, methods, properties at
runtime.
  1. What is an attribute in C#?
Answer: Metadata that provides information about code without being part
of the code itself.
  1. What is the difference between class and struct in memory allocation?
Answer:
Class: Stored on heap, reference type

Struct: Stored on stack, value type (unless boxed)
  1. What is the this keyword in a struct?
Answer: Refers to the current instance. In structs, this is a copy, not a
reference.
  1. What is the purpose of the using statement?
Answer: Ensures Dispose() is called on IDisposable objects, even if exceptions
occur.
  1. What is the difference between using statement and using declaration?
Answer:
Statement: Scope-based disposal
Declaration (C# 8.0+): Block-scoped disposal using using Type name =
new Type();
  1. What is variance in generics?
Answer: Covariance allows derived types where base types are expected;
contravariance allows base types where derived types are expected.
  1. What is the purpose of where constraints in generics?
Answer: Restrict the types that can be used as type arguments (e.g., where T
: class, where T : IDisposable).
  1. What is the difference between List and IEnumerable?
Answer:
List: Concrete collection, mutable, subscriptable
IEnumerable: Enumerable abstraction, read-only sequence
  1. What is LINQ?
Answer: Language Integrated Query - a set of methods and syntax for
querying data from various sources.
  1. What is the difference between IEnumerable and IEnumerable?
Answer:
IEnumerable: Non-generic, untyped enumeration
IEnumerable: Generic, type-safe enumeration
  1. What is deferred execution in LINQ?
Answer: LINQ queries are not executed until the result is enumerated (e.g.,
foreach, ToList()).
  1. What is the difference between immediate and deferred execution?
Answer:
Immediate: Executed immediately (ToList(), ToArray(), Count())
Deferred: Executed when enumerated (Where, Select, OrderBy)
  1. What is a delegate?
Answer: A type-safe function pointer. Represents a method with a specific
signature.
  1. What is the difference between Action and Func?
Answer:
Action: Method that takes parameters but returns void
Func<T, TResult>: Method that takes parameters and returns a result
  1. What is an event?
Answer: A wrapper around a delegate that allows safe subscription and
notification of subscribers.
  1. What is the difference between public field and property?
Answer:
Field: Direct member access
Property: Encapsulated access with get/set logic, validation,
notifications
  1. What is auto-property?
Answer: A property with automatically generated backing field, declared
concisely as public int Id { get; set; }.
  1. What is the difference between public and private?
Answer:
public: Accessible from outside the class
private: Accessible only within the class
  1. What is the purpose of readonly keyword?
Answer: Prevents modification after initialization (field can only be set in
constructor).
  1. What is the difference between readonly and const?
Answer:
const: Compile-time constant, inlined, must be initialized at declaration
readonly: Runtime constant, not inlined, can be initialized in
constructor
  1. **What is the null-coalescing operator (??)? **
Answer: Returns the left operand if it’s not null; otherwise, returns the right
operand.
  1. What is the null-conditional operator (?. and ?[])?
Answer: Safely accesses members/indexes on potentially null objects,
returning null instead of throwing an exception.
  1. What is the difference between checked and unchecked?
Answer:
checked: Throws OverflowException on numeric overflow
unchecked: Silently wraps around on overflow
  1. What is an indexer?
Answer: A property that allows instances to be indexed like arrays using []
syntax.
  1. What is a partial class?
Answer: A class definition split across multiple files using the partial
keyword.
  1. What is an extension method?
Answer: A static method that appears to be a method of another type,
extending it with new functionality.
  1. What are anonymous types?
Answer: Lightweight types created on-the-fly using new { Property = value }
syntax.
  1. What is the purpose of the sealed keyword?
Answer: Prevents a class from being inherited, ensuring the current
implementation is final.
  1. What is the purpose of the abstract keyword?
Answer: Marks a class or method as abstract, requiring derived classes to
implement it.
  1. What is the difference between abstract class and interface (revisited)?
Answer: Abstract classes can have state and implementation; interfaces
cannot (traditionally). Use interface for contracts, abstract class for shared
implementation.
  1. What is the purpose of default interface methods (C# 8.0+)?
Answer: Allows interfaces to provide method implementations, enabling
backward compatibility when adding new methods.
  1. What is the difference between is and as keywords?
Answer:
is: Checks if an object is an instance of a type (returns bool)
as: Attempts to cast; returns null if unsuccessful (doesn’t throw)
  1. What is pattern matching?
Answer: A feature that allows checking and extracting information from
objects using patterns.
  1. What is the purpose of namespaces?
Answer: Organize code and prevent naming conflicts by grouping types
under a hierarchy.
  1. What is the using directive?
Answer: Imports a namespace, allowing types to be accessed without the full
qualified name.
  1. What is the purpose of XML documentation comments (///?
Answer: Provides documentation for code elements that can be extracted
and used by IntelliSense and documentation generators.
  1. What is the difference between AppDomain and AssemblyLoadContext?
Answer: AppDomain (Framework) manages assemblies within a process;
AssemblyLoadContext (.NET Core) provides more granular control.
  1. What is the purpose of strong naming?
Answer: Cryptographically signs an assembly to ensure authenticity and
prevent version spoofing.
  1. What is a NuGet package?
    Answer: A package format for distributing reusable .NET libraries and tools.
  2. What is the difference between Debug and Release builds?
Answer:
Debug: Includes debugging symbols, no optimization, faster
compilation
Release: Optimized, smaller, faster execution, no symbols
  1. What is the purpose of the [Serializable] attribute?
Answer: Marks a class as serializable, allowing it to be converted to a byte
stream.
  1. What is the difference between DataContract and Serializable?
Answer:
[Serializable]: Binary serialization, requires [NonSerialized] for
exclusion
[DataContract]: Data contract serialization, requires [DataMember] for
inclusion

Real-World Scenarios

These are practical questions based on actual development

scenarios

  1. You have a Singleton Logger and a Scoped DbContext. How do you log from
    the DbContext without causing a captive dependency?
Answer: Inject ILoggerFactory (Singleton-safe) instead of ILogger. Or use a
factory pattern to get the logger when needed.
Code:

public class MyDbContext
{
private readonly ILoggerFactory _loggerFactory;

public MyDbContext(ILoggerFactory loggerFactory)
{
_loggerFactory = loggerFactory;
}
}
  1. You need to cache expensive operations. Should you use a Singleton cache
    service?
Answer: Yes, for application-level caching. Consider thread safety, memory
management, and invalidation strategies.
  1. Your async method is causing deadlocks in a UI context. What’s the solution?
Answer: Use ConfigureAwait(false) to avoid capturing the synchronization
context. Or ensure async all the way.
  1. You have a static utility class. Should you refactor it for testability?
Answer: If it depends on external services, yes. Extract an interface and use
DI. For pure utilities, static is fine.
  1. You need to implement the Unit of Work pattern. Should DbContext be
    Scoped?
Answer: Yes, DbContext should be Scoped. One context per logical unit of
work (typically per request).
  1. How do you implement a retry policy for a failed async operation?
Answer: Use Polly library with exponential backoff, or manually implement
retry logic in an async method.
  1. You have a background job that needs Scoped services. How do you handle
    it?
Answer: Create a scope manually: using var scope =
serviceProvider.CreateScope(); then resolve services.
  1. How do you prevent memory leaks from event subscriptions?
Answer: Unsubscribe from events, use weak event patterns, or ensure
subscribers are garbage collected.
  1. You need to validate dependencies at startup. How do you do this?
Answer: Use serviceProvider.GetRequiredService<T>() in startup code, or
enable ValidateOnBuild.
  1. How do you handle cross-cutting concerns like logging, security, and error
    handling?
Answer: Use decorator pattern with DI, middleware in ASP.NET Core, or
aspects with AOP libraries.
  1. You have a service that depends on configuration. Should it be Singleton?
Answer: Yes, if configuration doesn’t change during runtime. If it does,
consider Scoped.
  1. How do you implement a plugin architecture with DI?
Answer: Use AssemblyLoadContext to load assemblies dynamically, register
their services with the DI container.
  1. You need to mock static methods in unit tests. What’s the approach?
Answer: Wrap them in an interface/service and inject. Use libraries like Moles
or Shims for stubborn code.
  1. How do you handle async exceptions in a Task.WhenAll scenario?
Answer: Use try-catch around await WhenAll; all exceptions are aggregated
in AggregateException.
  1. You have a high-traffic application with memory pressure. Should you use
    Transient or Singleton?
Answer: Depends on object size and thread safety. Singleton for stateless,
large objects; Transient for small, stateful objects.
  1. How do you ensure that two Scoped services share the same instance within
    a request?
Answer: Register them both as Scoped in the same DI container. They’ll share
the same lifetime.
  1. You need to implement a factory pattern that returns different
    implementations. How?
Answer: Use a factory service registered in DI, returning implementations
based on conditions.
  1. How do you handle versioning of APIs with different dependencies?
Answer: Use keyed services, separate DI containers, or factory methods to
resolve different versions.
  1. You have circular dependencies between services. How do you refactor?
Answer: Introduce an event-based architecture, use a mediator pattern, or
lazy inject one service.
  1. How do you implement a decorator pattern for caching on top of a
    repository?
Answer:

services.AddScoped<IRepository>(sp =>
new CachedRepository(
new Repository(sp.GetService<IDbContext>()),
sp.GetService<ICache>()
)
);
  1. You need to inject named/keyed services based on configuration. How?
Answer: Use a factory method that reads configuration and resolves the
appropriate service.
  1. How do you test async methods that use ConfigureAwait(false)?
Answer: Create a synchronous test wrapper or use async test methods with
xUnit/NUnit.
  1. You have a static property that should be thread-safe. How?
Answer: Use lock, ThreadLocal, Interlocked, or Lazy for thread-safe
initialization.
  1. How do you implement a repository pattern with async operations?
Answer: Define async methods in IRepository interface (GetAsync,
SaveAsync) and implement in concrete repository.
  1. You need to handle graceful degradation in microservices. How do you
    structure services?
Answer: Use fallback services, circuit breakers, and abstract concerns behind
interfaces.
  1. How do you implement Command Query Responsibility Segregation (CQRS)
    with DI?
Answer: Register command and query handlers separately, use MediatR or
custom dispatcher, resolve based on request type.
  1. You need to implement soft delete functionality. Should it be in the
    repository or DbContext?
Answer: Implement with DbContext filters or repository methods. DbContext
filters are more transparent.
  1. How do you prevent N+1 query problems in Entity Framework?
Answer: Use .Include() for eager loading, projections with .Select(), or split
queries.
  1. You have a complex business logic that spans multiple services. How do you
    organize it?
Answer: Use a Domain-Driven Design approach with aggregates, domain
services, and application services.
  1. How do you monitor and optimize dependency resolution performance in
    production?
Answer: Use Diagnostic tools, measure service resolution time, profile
allocations, consider compiled DI containers.

Key Takeaways

Do’s:

Use DI for all dependencies
Keep classes focused (SRP)
Design for extension (OCP)
Use scoped for DbContext
Use async/await for I/O
Test async code properly

Don’ts:

Don’t use static for replaceable logic
Don’t return void from async methods
Don’t mix sync and async
Don’t ignore ConfigureAwait
Don’t create captive dependencies
Don’t use Service Locator pattern
