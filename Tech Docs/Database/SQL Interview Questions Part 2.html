1. CTEs (Common Table Expressions)

Basic

Q1. What is a CTE in SQL?

A CTE (Common Table Expression) is a named temporary result set defined using the WITH keyword that exists only for the duration of a single query.

WITH cte_name AS (
    SELECT department, COUNT(*) AS emp_count
    FROM employees
    GROUP BY department
)
SELECT * FROM cte_name WHERE emp_count > 5;

Q2. What is the syntax of a CTE?

WITH cte_name (col1, col2) AS (
    -- your query here
    SELECT col1, col2 FROM some_table
)
SELECT * FROM cte_name;

The column list after the CTE name is optional — you can also alias inside the SELECT.

Q3. Can you define multiple CTEs in a single query?

Yes, by separating them with commas.

WITH
dept_cte AS (
    SELECT department_id, department_name FROM departments
),
emp_cte AS (
    SELECT employee_id, department_id, salary FROM employees
)
SELECT e.employee_id, d.department_name, e.salary
FROM emp_cte e
JOIN dept_cte d ON e.department_id = d.department_id;

Q4. Is a CTE stored permanently in the database?

No. A CTE exists only during the execution of the query it is defined in. It is not stored as an object in the database.

Intermediate

Q5. What is a Recursive CTE? Give a use case.

A Recursive CTE is a CTE that references itself. It has two parts: an anchor (base case) and a recursive member.

-- Generate numbers 1 to 10
WITH RECURSIVE number_series AS (
    SELECT 1 AS n          -- Anchor
    UNION ALL
    SELECT n + 1           -- Recursive member
    FROM number_series
    WHERE n < 10
)
SELECT * FROM number_series;

Use cases: traversing hierarchical data (org charts, category trees), generating date series, BOM (Bill of Materials) explosion.

Q6. How do you traverse an employee hierarchy using a Recursive CTE?

WITH RECURSIVE emp_hierarchy AS (
    -- Anchor: top-level employees (no manager)
    SELECT employee_id, name, manager_id, 1 AS level
    FROM employees
    WHERE manager_id IS NULL

    UNION ALL

    -- Recursive: find their direct reports
    SELECT e.employee_id, e.name, e.manager_id, eh.level + 1
    FROM employees e
    INNER JOIN emp_hierarchy eh ON e.manager_id = eh.employee_id
)
SELECT * FROM emp_hierarchy ORDER BY level, manager_id;

Q7. Can a CTE be used in INSERT, UPDATE, DELETE statements?

Yes.

-- UPDATE using CTE
WITH above_avg AS (
    SELECT employee_id
    FROM employees
    WHERE salary > (SELECT AVG(salary) FROM employees)
)
UPDATE employees
SET bonus = salary * 0.10
WHERE employee_id IN (SELECT employee_id FROM above_avg);

Q8. Can you reference a CTE more than once in the same query?

Yes — this is one of the key advantages of CTEs over subqueries.

WITH sales_summary AS (
    SELECT product_id, SUM(amount) AS total_sales
    FROM sales
    GROUP BY product_id
)
SELECT
    s1.product_id,
    s1.total_sales,
    s1.total_sales / (SELECT SUM(total_sales) FROM sales_summary) * 100 AS pct
FROM sales_summary s1;

Advanced

Q9. Is a CTE materialized or does the optimizer inline it?

This is database-specific and often misunderstood:

  • PostgreSQL: CTEs are materialized by default (act as optimization fences). From PG 12+, non-recursive CTEs can be inlined using WITH ... AS NOT MATERIALIZED.
  • SQL Server: CTEs are typically inlined (not materialized). The optimizer treats them like subqueries and may evaluate them multiple times.
  • MySQL 8+: CTEs are inlined by default.
  • Oracle: CTEs can be materialized using the /*+ MATERIALIZE */ hint.

This matters for performance — if a CTE is referenced multiple times and not materialized, it may be executed multiple times.

Q10. What is an infinite loop risk in Recursive CTEs and how do you prevent it?

If the recursive condition never becomes false, the query runs forever. Prevention:

-- Use MAXRECURSION option (SQL Server)
WITH RECURSIVE ... 
OPTION (MAXRECURSION 100); -- Stops after 100 levels

-- OR add a depth/level counter
WHERE level < 10  -- Explicit termination in WHERE clause

MySQL default max recursion depth is 1000 (controlled by cte_max_recursion_depth).

Q11. Can you use ORDER BY inside a CTE definition?

Generally no — ORDER BY inside a CTE definition is not meaningful because a CTE is a result set, not an ordered list. You should ORDER BY in the outer query.

Some databases allow it only when used with TOP/LIMIT (to define which rows to pick), but not for ordering the CTE output itself.

Q12. What happens if you use a window function inside a CTE?

Perfectly valid and a very common pattern — CTEs are often used to isolate window function logic.

WITH ranked AS (
    SELECT
        employee_id,
        department_id,
        salary,
        RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rnk
    FROM employees
)
SELECT * FROM ranked WHERE rnk = 1; -- Top earner per department

2. Temp Tables

Basic

Q13. What is a Temp Table in SQL?

A Temp Table is a physical table stored temporarily (usually in tempdb in SQL Server or the temp schema in other databases). It persists for the duration of a session or transaction and can be indexed and queried like a regular table.

-- SQL Server / MySQL
CREATE TEMPORARY TABLE temp_high_salary (
    employee_id INT,
    name VARCHAR(100),
    salary DECIMAL(10,2)
);

INSERT INTO temp_high_salary
SELECT employee_id, name, salary FROM employees WHERE salary > 80000;

SELECT * FROM temp_high_salary;

Q14. What is the difference between a Local and Global Temp Table?

Local (#table) Global (##table)
Prefix # ##
Scope Current session/connection only All sessions
Dropped when Session ends or explicitly dropped Last session using it ends
Visibility Only creator All connections 
CREATE TABLE #local_temp (id INT);   -- Local
CREATE TABLE ##global_temp (id INT); -- Global (SQL Server)

Q15. How do you drop a Temp Table?

DROP TABLE IF EXISTS #temp_table;  -- SQL Server 2016+
DROP TEMPORARY TABLE IF EXISTS temp_table;  -- MySQL

In SQL Server, a local temp table is automatically dropped when the session ends.

Q16. Can you create indexes on a Temp Table?

Yes — this is a major advantage over CTEs for large datasets.

CREATE TABLE #temp_orders (
    order_id INT,
    customer_id INT,
    order_date DATE
);

CREATE INDEX idx_customer ON #temp_orders(customer_id);

Intermediate

Q17. What is a Table Variable and how does it differ from a Temp Table?

-- Table Variable (SQL Server)
DECLARE @table_var TABLE (
    id INT,
    name VARCHAR(100)
);
INSERT INTO @table_var SELECT employee_id, name FROM employees;
Temp Table (#) Table Variable (@)
Scope Session Batch/Procedure
Can be indexed Yes Only implicit PK/UNIQUE
Statistics Yes No (or minimal)
Transactions Participates fully Partially (not rolled back)
Best for Large datasets Small datasets

Q18. Are Temp Tables rolled back on transaction rollback?

Yes — unlike table variables, temp tables fully participate in transactions.

BEGIN TRANSACTION;
    CREATE TABLE #t (id INT);
    INSERT INTO #t VALUES (1);
ROLLBACK;
-- The #t table still exists but the INSERT is rolled back

Q19. Can a stored procedure access a Temp Table created outside it?

Yes — a local temp table created in an outer scope (calling session) is visible to the stored procedure it calls.

CREATE TABLE #shared_temp (id INT);
INSERT INTO #shared_temp VALUES (1);

EXEC my_stored_procedure; -- Can SELECT from #shared_temp

Advanced

Q20. What is the performance implication of Temp Tables vs Table Variables for large data?

  • Temp tables use full statistics → the query optimizer makes better execution plans for large data.
  • Table variables have no statistics (or cardinality = 1) → optimizer often underestimates row counts → poor plans.
  • For datasets > a few thousand rows, prefer temp tables.
  • For small datasets (lookup tables, < 100 rows), table variables are faster due to less overhead.

Q21. What is tempdb contention and how can Temp Tables cause it?

In SQL Server, heavy creation/dropping of temp tables creates metadata contention on tempdb system tables (like sysobjects). Mitigation strategies:

  • Increase number of tempdb data files (usually match CPU cores, up to 8).
  • Use table variables for small, frequently-created temp structures.
  • Use in-memory OLTP tables for extreme cases.

3. CTE vs Temp Table — Comparison Questions

Q22. What are the key differences between a CTE and a Temp Table?

Feature CTE Temp Table
Storage Not stored (logical) Physically stored in tempdb
Lifetime Single query only Session / until dropped
Indexes Not possible Possible
Reusability Within same query only Across multiple queries in session
Recursion Supported Not supported
Statistics No Yes
DML Supported Supported
Best for Readable, single-use logic Large data, multi-step processing

Q23. When would you choose a Temp Table over a CTE?

Use a Temp Table when:

  • The intermediate result set is large (hundreds of thousands of rows) and needs indexes.
  • You need to reuse the result across multiple queries or stored procedure steps.
  • You need statistics for the optimizer to build a good plan.
  • You’re doing iterative/procedural data processing.

Use a CTE when:

  • The query is read-once and the result set is small-to-medium.
  • You want recursion.
  • You want readable, self-documenting SQL without creating objects.
  • You’re writing ad-hoc queries.

Q24. Can a CTE replace a Temp Table in all scenarios?

No. CTEs cannot:

  • Be indexed
  • Be reused across query boundaries
  • Persist data between steps in a multi-step stored procedure
  • Handle very large intermediate results efficiently (no statistics)

Q25. What is an “optimization fence” in the context of CTEs?

In PostgreSQL (pre-12), a CTE is always materialized — the database computes and stores the result once, then the outer query reads from it. This prevents the optimizer from pushing predicates (like WHERE clauses) into the CTE, which can hurt performance. This is called an optimization fence.

-- PostgreSQL 12+: opt-out of materialization
WITH my_cte AS NOT MATERIALIZED (
    SELECT * FROM large_table
)
SELECT * FROM my_cte WHERE id = 5;
-- Now optimizer can push id=5 filter into the CTE

4. JOINs

Basic

Q26. What are the types of JOINs in SQL?

  • INNER JOIN — only matching rows from both tables
  • LEFT (OUTER) JOIN — all rows from left + matching from right (NULLs if no match)
  • RIGHT (OUTER) JOIN — all rows from right + matching from left
  • FULL (OUTER) JOIN — all rows from both; NULLs where no match
  • CROSS JOIN — Cartesian product (every row × every row)
  • SELF JOIN — a table joined with itself

Q27. What is the difference between INNER JOIN and LEFT JOIN?

-- Returns only employees who have a department
SELECT e.name, d.department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.department_id;

-- Returns ALL employees; NULL department_name if unassigned
SELECT e.name, d.department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.department_id;

Q28. What is a CROSS JOIN?

Returns the Cartesian product — every row from table A paired with every row from table B.

SELECT color, size
FROM colors
CROSS JOIN sizes;
-- If colors has 3 rows and sizes has 4 rows → 12 result rows

Use case: generating combinations (e.g., product variants, test matrices).

Q29. What is a SELF JOIN?

A table joined with itself, typically using aliases.

-- Find employees and their managers
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.employee_id;

Intermediate

Q30. What is a NON-EQUI JOIN?

A join using a condition other than = (e.g., >, <, BETWEEN).

-- Assign salary grades
SELECT e.name, e.salary, sg.grade
FROM employees e
JOIN salary_grades sg
    ON e.salary BETWEEN sg.min_salary AND sg.max_salary;

Q31. How do you find rows in Table A that have NO match in Table B?

Use a LEFT JOIN and filter for NULLs on the right side (anti-join pattern):

SELECT a.*
FROM table_a a
LEFT JOIN table_b b ON a.id = b.a_id
WHERE b.a_id IS NULL;

Or using NOT EXISTS:

SELECT * FROM table_a a
WHERE NOT EXISTS (
    SELECT 1 FROM table_b b WHERE b.a_id = a.id
);

Q32. What is the difference between WHERE and ON in a JOIN?

  • ON defines the join condition (how rows are matched).
  • WHERE filters rows after the join is performed.

For INNER JOIN, the result is the same. For OUTER JOIN, it matters:

-- Returns all employees, but only with active department info
SELECT e.name, d.department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.department_id AND d.is_active = 1;

-- Filters OUT employees without a department (loses LEFT JOIN behavior)
SELECT e.name, d.department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.department_id
WHERE d.is_active = 1;

This is one of the most commonly ignored interview traps.

Q33. Can you JOIN on multiple conditions?

Yes.

SELECT *
FROM orders o
JOIN order_details od
    ON o.order_id = od.order_id
    AND o.year = od.year;

Q34. What is the execution order of SQL clauses including JOINs?

FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT/TOP

Advanced

Q35. What is a LATERAL JOIN (or APPLY in SQL Server)?

A LATERAL JOIN (PostgreSQL) or CROSS APPLY / OUTER APPLY (SQL Server) allows the right-hand table expression to reference columns from the left-hand table — like a correlated subquery in the FROM clause.

-- SQL Server: Get top 2 orders per customer
SELECT c.customer_id, o.order_id, o.amount
FROM customers c
CROSS APPLY (
    SELECT TOP 2 order_id, amount
    FROM orders
    WHERE customer_id = c.customer_id
    ORDER BY amount DESC
) o;

Q36. What is the difference between CROSS APPLY and OUTER APPLY?

CROSS APPLY OUTER APPLY
Behavior Like INNER JOIN — excludes rows where subquery returns nothing Like LEFT JOIN — includes rows even if subquery returns nothing

Q37. What happens when you JOIN on a NULL value?

NULL does not equal NULL in SQL (NULL = NULL is UNKNOWN, not TRUE). So rows with NULL in the join key will not match.

-- These two rows will NOT join even though both have NULL department_id
INSERT INTO employees VALUES (1, 'Alice', NULL);
INSERT INTO employees VALUES (2, 'Bob', NULL);

SELECT * FROM employees e JOIN employees e2 ON e.department_id = e2.department_id;
-- Neither Alice nor Bob will appear

To match NULLs explicitly:

ON (e.department_id = e2.department_id OR (e.department_id IS NULL AND e2.department_id IS NULL))

Q38. How do JOINs work with duplicate rows? What is a “join explosion”?

If there are duplicate values in the join key, you get a multiplicative effect:

-- Table A has 3 rows with department_id = 5
-- Table B has 4 rows with department_id = 5
-- INNER JOIN produces 3 × 4 = 12 rows for department_id = 5

This is called a join explosion and is a common source of incorrect aggregations. Always check for duplicate keys before joining, or use DISTINCT/GROUP BY to deduplicate first.

Q39. What is the difference between a HASH JOIN, MERGE JOIN, and NESTED LOOP JOIN?

These are join algorithms chosen by the query optimizer:

Algorithm How it works Best for
Nested Loop For each row in outer table, scan inner table Small tables, indexed inner table
Hash Join Build hash table on smaller input, probe with larger Large unsorted tables, equi-joins
Merge Join Sort both inputs then merge Large sorted/indexed tables, equi-joins

You don’t choose these — the optimizer does. But understanding them helps in query tuning.

5. GROUP BY & HAVING

Basic

Q40. What does GROUP BY do?

GROUP BY collapses rows with the same value(s) in specified column(s) into a single row, usually used with aggregate functions.

SELECT department_id, COUNT(*) AS headcount, AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id;

Q41. What is the difference between WHERE and HAVING?

  • WHERE filters rows before grouping.
  • HAVING filters groups after GROUP BY.
-- WHERE filters individual rows
-- HAVING filters the grouped result
SELECT department_id, AVG(salary) AS avg_sal
FROM employees
WHERE is_active = 1           -- Filter before grouping
GROUP BY department_id
HAVING AVG(salary) > 60000;  -- Filter after grouping

Q42. Can you use HAVING without GROUP BY?

Yes — it treats the entire result set as one group.

SELECT COUNT(*) AS total
FROM employees
HAVING COUNT(*) > 100;

Q43. Can you GROUP BY multiple columns?

Yes — creates groups for each unique combination of values.

SELECT department_id, job_title, COUNT(*) AS cnt
FROM employees
GROUP BY department_id, job_title;

Intermediate

Q44. Can you use an alias defined in SELECT inside HAVING?

In most databases (MySQL, PostgreSQL), no — HAVING is evaluated before SELECT aliases are applied. Use the full expression:

-- WRONG in SQL Server / Oracle
SELECT department_id, AVG(salary) AS avg_sal
FROM employees
GROUP BY department_id
HAVING avg_sal > 60000; -- Error in many DBs

-- CORRECT
HAVING AVG(salary) > 60000;

MySQL allows alias in HAVING as a special case.

Q45. What columns must appear in GROUP BY?

Any column in the SELECT list that is NOT inside an aggregate function must appear in GROUP BY.

-- WRONG
SELECT department_id, name, COUNT(*)  -- 'name' not aggregated or grouped
FROM employees
GROUP BY department_id;

-- CORRECT
SELECT department_id, COUNT(*)
FROM employees
GROUP BY department_id;

Exception: MySQL with ONLY_FULL_GROUP_BY mode disabled allows this (but returns non-deterministic values).

Q46. Can you use GROUP BY with a JOIN?

Yes — very common pattern.

SELECT d.department_name, COUNT(e.employee_id) AS headcount
FROM departments d
LEFT JOIN employees e ON d.department_id = e.department_id
GROUP BY d.department_id, d.department_name
HAVING COUNT(e.employee_id) > 0;

Q47. What is GROUPING SETS?

GROUPING SETS allows multiple GROUP BY groupings in a single query — avoids multiple UNION ALL statements.

SELECT department_id, job_title, COUNT(*) AS cnt
FROM employees
GROUP BY GROUPING SETS (
    (department_id),
    (job_title),
    ()  -- Grand total
);

Q48. What is ROLLUP?

ROLLUP generates subtotals and a grand total along a hierarchy.

SELECT year, quarter, SUM(sales)
FROM sales_data
GROUP BY ROLLUP(year, quarter);
-- Produces: per year+quarter, per year only, grand total

Q49. What is CUBE?

CUBE generates all possible combinations of grouping.

SELECT region, product, SUM(sales)
FROM sales_data
GROUP BY CUBE(region, product);
-- All combinations: (region, product), (region), (product), ()

Advanced

Q50. What is the GROUPING() function?

GROUPING() returns 1 if the column is NULL because of ROLLUP/CUBE aggregation (not a real NULL), 0 otherwise.

SELECT
    CASE WHEN GROUPING(department_id) = 1 THEN 'ALL DEPTS' ELSE CAST(department_id AS VARCHAR) END AS dept,
    SUM(salary) AS total_salary
FROM employees
GROUP BY ROLLUP(department_id);

Q51. Can you GROUP BY an expression or function result?

Yes.

SELECT YEAR(hire_date) AS hire_year, COUNT(*) AS hires
FROM employees
GROUP BY YEAR(hire_date);

-- Or using ordinal position (MySQL/PostgreSQL)
SELECT YEAR(hire_date), COUNT(*)
FROM employees
GROUP BY 1;

Q52. What is the difference between COUNT(*), COUNT(col), and COUNT(DISTINCT col)?

SELECT
    COUNT(*)            AS total_rows,       -- All rows including NULLs
    COUNT(manager_id)   AS non_null_manager, -- Excludes NULLs
    COUNT(DISTINCT manager_id) AS unique_managers -- Distinct non-NULL values
FROM employees;

Q53. Tricky: What does this query return?

SELECT department_id, AVG(salary)
FROM employees
WHERE AVG(salary) > 50000
GROUP BY department_id;

Answer: This throws an error. You cannot use aggregate functions in WHERE. Use HAVING instead.

6. SQL Functions

String Functions

Q54. What are common string functions in SQL?

SELECT
    UPPER('hello')              AS upper_case,   -- HELLO
    LOWER('WORLD')              AS lower_case,   -- world
    LEN('hello')                AS length,       -- 5 (SQL Server: LEN, MySQL/PG: LENGTH)
    TRIM('  hello  ')           AS trimmed,      -- hello
    LTRIM('  hello')            AS left_trim,
    RTRIM('hello  ')            AS right_trim,
    SUBSTRING('hello', 2, 3)    AS substr,       -- ell
    LEFT('hello', 3)            AS left_3,       -- hel
    RIGHT('hello', 3)           AS right_3,      -- llo
    REPLACE('hello', 'l', 'r')  AS replaced,     -- herro
    CHARINDEX('l', 'hello')     AS position,     -- 3 (SQL Server); use INSTR in MySQL/Oracle
    CONCAT('Hello', ' ', 'SQL') AS concatenated, -- Hello SQL
    REVERSE('hello')            AS reversed;     -- olleh

Q55. What is the difference between CHAR and NCHAR functions?

  • CHAR(n) returns the ASCII character for the given code.
  • NCHAR(n) returns the Unicode character.
SELECT CHAR(65);   -- A
SELECT NCHAR(9786); -- ☺

Q56. What is COALESCE and how is it different from ISNULL?

-- COALESCE: ANSI standard, accepts multiple arguments, returns first non-NULL
SELECT COALESCE(NULL, NULL, 'third', 'fourth'); -- 'third'

-- ISNULL: SQL Server only, accepts exactly 2 arguments
SELECT ISNULL(NULL, 'fallback'); -- 'fallback'

-- NULLIF: returns NULL if two values are equal, else returns first value
SELECT NULLIF(5, 5);   -- NULL
SELECT NULLIF(5, 10);  -- 5

Date Functions

Q57. What are common date functions?

-- SQL Server
SELECT
    GETDATE()                        AS current_datetime,
    GETUTCDATE()                     AS utc_datetime,
    CAST(GETDATE() AS DATE)          AS today,
    YEAR(GETDATE())                  AS yr,
    MONTH(GETDATE())                 AS mo,
    DAY(GETDATE())                   AS dy,
    DATEADD(DAY, 30, GETDATE())      AS plus_30_days,
    DATEDIFF(DAY, '2024-01-01', GETDATE()) AS days_since,
    DATENAME(WEEKDAY, GETDATE())     AS day_name,
    EOMONTH(GETDATE())               AS end_of_month,
    FORMAT(GETDATE(), 'yyyy-MM-dd')  AS formatted;

-- MySQL equivalents
SELECT
    NOW(), CURDATE(), CURTIME(),
    DATE_ADD(NOW(), INTERVAL 30 DAY),
    DATEDIFF(NOW(), '2024-01-01'),
    DATE_FORMAT(NOW(), '%Y-%m-%d'),
    LAST_DAY(NOW());

Q58. How do you extract the first day and last day of the current month?

-- SQL Server
SELECT
    DATEFROMPARTS(YEAR(GETDATE()), MONTH(GETDATE()), 1)  AS first_day,
    EOMONTH(GETDATE())                                    AS last_day;

-- MySQL
SELECT
    DATE_FORMAT(NOW(), '%Y-%m-01') AS first_day,
    LAST_DAY(NOW())                AS last_day;

Aggregate Functions

Q59. What aggregate functions are available in SQL?

SELECT
    COUNT(*)       AS row_count,
    SUM(salary)    AS total_salary,
    AVG(salary)    AS average_salary,
    MIN(salary)    AS min_salary,
    MAX(salary)    AS max_salary,
    STDEV(salary)  AS std_dev,       -- SQL Server
    VAR(salary)    AS variance,      -- SQL Server
    STRING_AGG(name, ', ') AS names  -- SQL Server 2017+, PostgreSQL
FROM employees;

Q60. What is STRING_AGG and how is it used?

Concatenates row values into a delimited string within a group.

SELECT department_id,
    STRING_AGG(name, ', ') WITHIN GROUP (ORDER BY name) AS employee_names
FROM employees
GROUP BY department_id;
-- Result: "Alice, Bob, Charlie" for each department

MySQL equivalent: GROUP_CONCAT(name ORDER BY name SEPARATOR ', ')

Window (Analytic) Functions

Q61. What are Window Functions in SQL?

Window functions perform calculations across a window of rows related to the current row, without collapsing them into groups. They use the OVER() clause.

SELECT
    employee_id,
    salary,
    AVG(salary) OVER () AS company_avg,
    AVG(salary) OVER (PARTITION BY department_id) AS dept_avg,
    salary - AVG(salary) OVER (PARTITION BY department_id) AS diff_from_dept_avg
FROM employees;

Q62. What is the difference between RANK(), DENSE_RANK(), and ROW_NUMBER()?

SELECT
    name,
    salary,
    ROW_NUMBER()  OVER (ORDER BY salary DESC) AS row_num,   -- Unique, no ties
    RANK()        OVER (ORDER BY salary DESC) AS rnk,       -- Ties get same rank; next rank skips
    DENSE_RANK()  OVER (ORDER BY salary DESC) AS dense_rnk  -- Ties get same rank; next rank does NOT skip
FROM employees;
Name Salary ROW_NUMBER RANK DENSE_RANK
A 90000 1 1 1
B 90000 2 1 1
C 80000 3 3 2

Q63. What is PARTITION BY in a Window Function?

PARTITION BY divides the rows into groups (partitions) before applying the window function — similar to GROUP BY but without collapsing rows.

SELECT
    department_id,
    employee_id,
    salary,
    SUM(salary) OVER (PARTITION BY department_id) AS dept_total
FROM employees;
-- Each row shows its own salary AND the department's total salary

Q64. What is the difference between PARTITION BY and GROUP BY?

GROUP BY PARTITION BY (Window)
Output rows Collapses to one row per group Keeps all original rows
Use case Aggregate summaries Per-row calculations with group context
Can mix aggregated and non-aggregated No Yes

Q65. What are LAG() and LEAD() functions?

LAG accesses a previous row’s value; LEAD accesses a future row’s value — within the same partition.

SELECT
    sale_date,
    amount,
    LAG(amount, 1, 0)  OVER (ORDER BY sale_date) AS prev_day_amount,
    LEAD(amount, 1, 0) OVER (ORDER BY sale_date) AS next_day_amount,
    amount - LAG(amount, 1, 0) OVER (ORDER BY sale_date) AS day_over_day_change
FROM daily_sales;

Q66. What is the frame clause in a Window Function?

The frame defines which rows (relative to the current row) are included in the window calculation.

SELECT
    sale_date,
    amount,
    -- Rolling 3-day average (current + 2 preceding)
    AVG(amount) OVER (
        ORDER BY sale_date
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS rolling_3_day_avg,
    -- Running total
    SUM(amount) OVER (
        ORDER BY sale_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total
FROM daily_sales;

Frame types:

  • ROWS BETWEEN ... — physical rows
  • RANGE BETWEEN ... — logical range (considers ties)

Q67. What is NTILE()?

Divides rows into N equal buckets and assigns a bucket number.

SELECT
    employee_id,
    salary,
    NTILE(4) OVER (ORDER BY salary DESC) AS quartile
FROM employees;
-- Quartile 1 = top 25%, Quartile 4 = bottom 25%

Q68. What is FIRST_VALUE() and LAST_VALUE()?

Returns the first or last value in the window frame.

SELECT
    department_id,
    name,
    salary,
    FIRST_VALUE(name) OVER (PARTITION BY department_id ORDER BY salary DESC) AS top_earner,
    LAST_VALUE(name)  OVER (
        PARTITION BY department_id ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS lowest_earner
FROM employees;

Note: LAST_VALUE requires explicit frame — by default the frame ends at the current row, not the partition end. This is a commonly missed gotcha.

Conditional Functions

Q69. What is the difference between CASE WHEN and IIF?

-- CASE WHEN: ANSI standard, multiple conditions
SELECT name,
    CASE
        WHEN salary >= 100000 THEN 'Senior'
        WHEN salary >= 60000  THEN 'Mid-level'
        ELSE 'Junior'
    END AS level
FROM employees;

-- IIF: SQL Server shorthand for simple if-else
SELECT name, IIF(salary >= 100000, 'Senior', 'Not Senior') AS level
FROM employees;

Q70. What is the difference between simple CASE and searched CASE?

-- Simple CASE: compares one expression to multiple values
SELECT CASE department_id
    WHEN 1 THEN 'Engineering'
    WHEN 2 THEN 'Marketing'
    ELSE 'Other'
END FROM employees;

-- Searched CASE: evaluates each condition independently (more flexible)
SELECT CASE
    WHEN salary > 100000 AND department_id = 1 THEN 'Senior Engineer'
    WHEN salary > 80000 THEN 'Experienced'
    ELSE 'Standard'
END FROM employees;

Commonly Ignored / Tricky Questions

Q71. Can a window function be used in a WHERE clause?

No. Window functions are executed after WHERE. To filter on a window function result, use a subquery or CTE:

-- WRONG
SELECT * FROM employees
WHERE RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) = 1;

-- CORRECT
WITH ranked AS (
    SELECT *, RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rnk
    FROM employees
)
SELECT * FROM ranked WHERE rnk = 1;

Q72. What is the difference between UNION and UNION ALL?

SELECT city FROM customers
UNION          -- Removes duplicates (implicit DISTINCT — slower)
SELECT city FROM suppliers;

SELECT city FROM customers
UNION ALL      -- Keeps all rows including duplicates (faster)
SELECT city FROM suppliers;

Always prefer UNION ALL when you know there are no duplicates or you don’t need deduplication.

Q73. What is EXCEPT / MINUS and INTERSECT?

-- EXCEPT (SQL Server/PostgreSQL) / MINUS (Oracle): rows in A but not in B
SELECT employee_id FROM employees
EXCEPT
SELECT employee_id FROM resigned_employees;

-- INTERSECT: rows present in BOTH
SELECT product_id FROM this_year_sales
INTERSECT
SELECT product_id FROM last_year_sales;

Q74. What is the difference between a scalar subquery and a correlated subquery?

-- Scalar subquery: runs once, returns one value
SELECT name, salary,
    (SELECT AVG(salary) FROM employees) AS avg_sal
FROM employees;

-- Correlated subquery: runs once PER ROW, references outer query
SELECT name, salary
FROM employees e1
WHERE salary > (
    SELECT AVG(salary)
    FROM employees e2
    WHERE e2.department_id = e1.department_id  -- references outer e1
);

Correlated subqueries can be slow on large tables — consider rewriting as JOINs or CTEs.

Q75. What is the OVER() clause without PARTITION BY?

OVER() with an empty parenthesis applies the window function over the entire result set as a single partition.

SELECT
    employee_id,
    salary,
    SUM(salary) OVER ()  AS grand_total,  -- Total of ALL rows
    salary / SUM(salary) OVER () * 100 AS pct_of_total
FROM employees;
