SQL Survival Guide: Keys, Triggers & Window Functions

*Notes that don’t feel like homework.

PART 1: KEYS — Database ke “ID Cards”

Think of a database table like a school. Every student needs to be uniquely identified. That’s what keys do.

Primary Key

“Only 1 in the table. Unique. Never NULL.”

  • Uniquely identifies each row in a table.
  • Only one Primary Key per table (but it can be composite!).
  • Automatically creates a clustered index (in most DBs).
CREATE TABLE students (
  student_id INT PRIMARY KEY,
  name VARCHAR(100)
);

Interview Trap: Can a Primary Key have multiple columns?
Yes! That’s called a Composite Primary Key.

PRIMARY KEY (order_id, product_id)  -- composite

Foreign Key

“Reference of another table (creates relation)”

  • Links two tables together (Parent → Child relationship).
  • References the Primary Key of another table.
  • Enforces Referential Integrity — you can’t add an order for a customer that doesn’t exist!
CREATE TABLE orders (
  order_id INT PRIMARY KEY,
  customer_id INT,
  FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);

Real talk: ON DELETE CASCADE → if parent is deleted child will also be deleted.
ON DELETE SET NULL → child’s FK column will also be null.

Unique Key

“Almost like Primary Key, but chill.”

  • Also enforces uniqueness — no duplicates allowed.
  • BUT it can have one NULL value (unlike PK which can’t be NULL).
  • A table can have multiple Unique Keys.
CREATE TABLE users (
  user_id INT PRIMARY KEY,
  email VARCHAR(255) UNIQUE   -- yeh hai unique key
);
Feature Primary Key Unique Key
NULL allowed? ❌ No One NULL allowed
How many per table? Only 1 Multiple
Index type Clustered Non-clustered

Candidate Key

“Qualifies as primary key but not selected as one.”

  • Any column (or combo) that could be a Primary Key.
  • All Primary Keys are Candidate Keys, but not vice versa.

Example: In a students table — student_id, email, aadhar_no — all three are unique. All three are Candidate Keys. But you picked student_id as PK.

Super Key

“Like a big brother to Candidate key but with extra baggage”

  • Any set of columns that uniquely identifies a row.
  • Candidate Key = minimal Super Key (no extra columns).
Super Key: {student_id, name}  ← works but 'name' is extra
Candidate Key: {student_id}    ← minimal, no extras

⚪ Alternate Key

“Runner-up. Qualified but not selected.”

  • Candidate Keys that were NOT chosen as the Primary Key.

Composite Key

“Tag-team key. one column is not enough so two or more columns work together.”

  • A key made of two or more columns combined.
  • Used when no single column is unique enough.
-- student_id + course_id together = unique enrollment
PRIMARY KEY (student_id, course_id)

PART 2: TRIGGERS — “Security guards of database”

Trigger = automatic action fires when INSERT / UPDATE / DELETE happens.

What is a Trigger?

A stored procedure that automatically executes in response to certain events on a table. you don’t call it manually it fires on its own.

CREATE TRIGGER trigger_name
{ BEFORE | AFTER | INSTEAD OF }
{ INSERT | UPDATE | DELETE }
ON table_name
FOR EACH ROW
BEGIN
  -- your logic here
END;

BEFORE vs AFTER Trigger

Type When it fires Common Use
BEFORE Before the operation happens Validate / modify data before saving
AFTER After the operation completes Logging, audit trails, notifications
INSTEAD OF Replaces the operation Used on Views

Trigger Example — Audit Log

-- whenever salary is updated old salary is saved in the log table
CREATE TRIGGER salary_audit
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN
  INSERT INTO salary_log (emp_id, old_salary, new_salary, changed_at)
  VALUES (OLD.emp_id, OLD.salary, NEW.salary, NOW());
END;

OLD = row before change
NEW = row after change

Types of Triggers

Type Description
Row-level (FOR EACH ROW) Fires for every row affected
Statement-level Fires once per SQL statement (even if 1000 rows affected)
DDL Trigger Fires on schema changes (CREATE, DROP, ALTER)
DML Trigger Fires on data changes (INSERT, UPDATE, DELETE)
INSTEAD OF Used on views, replaces the actual operation

Trigger Gotchas (Interview Gold!)

  • Triggers can cascade — one trigger firing another. Infinite loop ka risk!
  • Hard to debug — code mein visible nahi hota, silently runs.
  • Trigger mein COMMIT / ROLLBACK directly nahi kar sakte (most DBs).
  • Overusing triggers = performance issues on bulk operations.

PART 3: RANK vs DENSE_RANK vs ROW_NUMBER

“Teen bhai. Ek hi kaam — rank karna. But style alag alag.”

These are all Window Functions — they rank rows within a partition without collapsing the result set.

The Setup — Same Syntax for All Three

RANK()       OVER (PARTITION BY dept ORDER BY salary DESC)
DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC)
ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC)

The Classic Example

Name Salary RANK DENSE_RANK ROW_NUMBER
Alice 90000 1 1 1
Bob 85000 2 2 2
Charlie 85000 2 2 3
Diana 70000 4 3 4

The Key Difference

Function Tie pe kya hota hai? Gap aata hai?
ROW_NUMBER() Tied rows ko alag rank deta hai (arbitrary) No gaps
RANK() Tied rows ko same rank deta hai Gap aata hai (1,2,2,4)
DENSE_RANK() Tied rows ko same rank deta hai No gap (1,2,2,3)

When to Use Which?

  • ROW_NUMBER() → Jab har row ka unique number chahiye, tie doesn’t matter. Pagination ke liye perfect.
  • RANK() → Competition-style ranking (Olympic medals: 2 silvers → next is 4th, no 3rd).
  • DENSE_RANK() → Jab tied items ke baad continuity chahiye (Top-N queries, leaderboards).

Real Query — Top 3 Salaries per Department (No Duplicates issue)

-- RANK se problem: tied ranks pe gaps
SELECT name, dept, salary,
       RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rnk
FROM employees;

-- DENSE_RANK se better for "top 3 unique salary levels"
SELECT * FROM (
  SELECT name, dept, salary,
         DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS dr
  FROM employees
) t
WHERE dr <= 3;

ROW_NUMBER for Pagination

SELECT * FROM (
  SELECT *, ROW_NUMBER() OVER (ORDER BY created_at DESC) AS rn
  FROM orders
) t
WHERE rn BETWEEN 11 AND 20;  -- Page 2 (10 items per page)

INTERVIEW QUESTIONS

Keys

  1. What is the difference between Primary Key and Unique Key?
    (NULL allowed in Unique, only 1 PK per table, clustered vs non-clustered index)

  2. Can a table have no Primary Key?
    (Technically yes — it becomes a “heap”. But bad practice.)

  3. What is a Composite Key? When would you use it?

  4. What is Referential Integrity? How does Foreign Key enforce it?

  5. Difference between Candidate Key and Super Key?
    (Candidate = minimal super key)

  6. What happens when you delete a parent row that has child rows referencing it?
    (Depends on: ON DELETE CASCADE, SET NULL, RESTRICT, NO ACTION)

  7. Can a Foreign Key reference a Unique Key instead of Primary Key?
    (Yes! FK just needs to reference a column with a unique constraint)

  8. Can a Primary Key be NULL? Can a Unique Key?
    (PK: Never. Unique: One NULL allowed in most DBs)

  9. What is the difference between a Natural Key and a Surrogate Key?
    (Natural = real-world attribute like Aadhar; Surrogate = system-generated like id INT AUTO_INCREMENT)

  10. Why is using email as a Primary Key a bad idea?
    (Emails change, long strings = slower index, storage overhead)

Triggers

  1. What is a Trigger? When would you use one?

  2. Difference between BEFORE and AFTER triggers?

  3. What are OLD and NEW in a trigger?

  4. Can a trigger call another trigger? What’s the risk?
    (Yes — cascading triggers, infinite loop risk)

  5. What is an INSTEAD OF trigger? Where is it used?
    (Used on Views — replaces the DML operation with custom logic)

  6. Can you use COMMIT/ROLLBACK inside a trigger?
    (Most DBs don’t allow it — trigger runs within the calling transaction)

  7. What are the disadvantages of triggers?
    (Hard to debug, hidden business logic, performance on bulk ops, cascading complexity)

  8. Difference between Row-level and Statement-level triggers?

  9. Can a trigger modify the same table it’s defined on?
    (Can cause infinite recursion — most DBs prevent this or require careful guards)

  10. How is a Trigger different from a Stored Procedure?
    (Trigger = auto-fires on event; SP = manually called)

RANK vs DENSE_RANK

  1. What is the difference between RANK() and DENSE_RANK()?
    (RANK has gaps after ties; DENSE_RANK does not)

  2. What does ROW_NUMBER() do differently from RANK()?
    (ROW_NUMBER gives unique sequential numbers even for ties — no concept of “same rank”)

  3. Write a query to find the 2nd highest salary in each department.

SELECT * FROM (
  SELECT name, dept, salary,
         DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS dr
  FROM employees
) t WHERE dr = 2;

  1. What is the OVER() clause? What does PARTITION BY do?
    (OVER defines the window; PARTITION BY resets the ranking within each group)

  2. If two employees have the same salary and you use RANK(), what ranks will the next employee get?
    (Skips — e.g., two at rank 2, next gets rank 4)

  3. When would you use ROW_NUMBER() over RANK()?
    (When you need unique IDs per row, like pagination or deduplication)

  4. How do you get the top N records per group using window functions?

SELECT * FROM (
  SELECT *, RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS r
  FROM employees
) t WHERE r <= 3;

  1. Can you use WHERE clause directly on a window function alias?
    (No — window functions can’t be in WHERE. Use a subquery or CTE)

  2. What is the difference between RANK() and NTILE()?
    (RANK = rank each row; NTILE(n) = divides rows into n equal buckets)

  3. Write a query to remove duplicate rows keeping the latest entry using ROW_NUMBER().

DELETE FROM orders WHERE id IN (
  SELECT id FROM (
    SELECT id, ROW_NUMBER() OVER (PARTITION BY order_ref ORDER BY created_at DESC) AS rn
    FROM orders
  ) t WHERE rn > 1
);

“Keys organize your data. Triggers protect it. Window functions help you analyze it. Master all three and SQL interviews won’t scare you anymore.”
