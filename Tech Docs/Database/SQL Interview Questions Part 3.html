SQL Interview Questions: Keys, Triggers & Ranking Functions

From Basic to Advanced — Including the Questions People Usually Skip

TABLE OF CONTENTS

  1. Keys in SQL
  2. Triggers in SQL

1. KEYS IN SQL

BASIC LEVEL

Q1. What is a key in SQL?

A key is a single column or combination of columns used to uniquely identify rows in a table, or to establish relationships between tables.

Q2. What are the different types of keys in SQL?

Key Type Purpose
Primary Key Uniquely identifies each row in a table
Foreign Key Links two tables by referencing the primary key of another table
Unique Key Ensures all values in a column (or set of columns) are unique
Candidate Key Any column or combination that could serve as a primary key
Composite Key A key made up of more than one column
Surrogate Key An artificial/system-generated key (e.g., auto-increment ID)
Natural Key A key based on real-world data (e.g., Aadhar number, email)
Super Key Any set of columns that can uniquely identify a row (superset of candidate keys)
Alternate Key A candidate key that was not chosen as the primary key

Q3. What is a Primary Key? What are its properties?

A Primary Key uniquely identifies each row in a table.

Properties:

  • Must be UNIQUE (no two rows can have the same PK value)
  • Cannot be NULL
  • A table can have only ONE primary key
  • Can be a single column or a composite of multiple columns
-- Single column PK
CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    name VARCHAR(100)
);

-- Composite PK
CREATE TABLE order_items (
    order_id INT,
    product_id INT,
    quantity INT,
    PRIMARY KEY (order_id, product_id)
);

Q4. What is a Foreign Key?

A Foreign Key is a column (or set of columns) in one table that references the Primary Key of another table. It enforces referential integrity — meaning you can’t insert a value in the FK column that doesn’t exist in the referenced table.

CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);

Q5. What is a Unique Key? How is it different from a Primary Key?

Feature Primary Key Unique Key
NULL allowed? NO YES (one NULL in most DBs)
Number per table Only ONE Multiple allowed
Purpose Row identity Prevent duplicate values
Implicit index Clustered index (usually) Non-clustered index 
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    email VARCHAR(255) UNIQUE,
    phone VARCHAR(15) UNIQUE
);

Q6. What is a Composite Key?

A key made up of two or more columns together that uniquely identify a row. Neither column alone is unique enough.

-- Neither student_id alone nor course_id alone is unique.
-- Together, they identify one enrollment.
CREATE TABLE enrollments (
    student_id INT,
    course_id INT,
    enrolled_date DATE,
    PRIMARY KEY (student_id, course_id)
);

INTERMEDIATE LEVEL

Q7. What is the difference between a Candidate Key and a Primary Key?

  • A Candidate Key is any column or set of columns that could uniquely identify a row and has no NULL values.
  • A table can have multiple candidate keys.
  • The Primary Key is the one candidate key that is actually chosen to be the official identifier.
  • All other candidate keys become Alternate Keys.

Example: In an employees table, both emp_id and email could be candidate keys. If emp_id is chosen as the PK, then email becomes an alternate key.

Q8. What is a Super Key?

A Super Key is any set of one or more columns that can uniquely identify a row. It is a superset of candidate keys.

Example: If emp_id alone uniquely identifies a row, then {emp_id}, {emp_id, name}, {emp_id, name, dept} are all super keys.

A Candidate Key is the minimal super key — no column can be removed from it while still retaining uniqueness.

Q9. What is a Surrogate Key vs a Natural Key? When do you use each?

Surrogate Key Natural Key
Definition System-generated, has no business meaning Derived from actual business data
Example AUTO_INCREMENT id, UUID Aadhar number, PAN, email
Pros Stable, simple, never changes Self-documenting, meaningful
Cons Meaningless outside DB Can change in real world, may be long

When to use Surrogate: When natural keys are long, composite, or prone to change.
When to use Natural: When the key is truly immutable and simple (rare in practice).

Q10. Can a table have no Primary Key?

Yes, technically a table can be created without a primary key. However, it is very bad practice because:

  • You can have duplicate rows with no way to distinguish them.
  • JOINs and data integrity suffer.
  • Replication in MySQL requires a PK on each table.

Such tables are called heap tables in some databases.

Q11. Can a Foreign Key reference a Unique Key instead of a Primary Key?

Yes! A Foreign Key can reference any column (or set of columns) in the parent table that has a UNIQUE constraint, not just the Primary Key.

CREATE TABLE departments (
    dept_id INT PRIMARY KEY,
    dept_code VARCHAR(10) UNIQUE   -- unique key
);

CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    dept_code VARCHAR(10),
    FOREIGN KEY (dept_code) REFERENCES departments(dept_code)
    -- referencing UNIQUE key, not PK
);

Q12. What is a self-referencing Foreign Key?

A Foreign Key where a column in a table references the Primary Key of the same table. Commonly used for hierarchical/tree data.

CREATE TABLE employees (
    emp_id INT PRIMARY KEY,
    name VARCHAR(100),
    manager_id INT,
    FOREIGN KEY (manager_id) REFERENCES employees(emp_id)
    -- An employee's manager is also an employee
);

Q13. What are the ON DELETE and ON UPDATE actions for Foreign Keys?

These control what happens to child rows when a parent row is deleted or updated.

Action Behavior
CASCADE Automatically delete/update child rows
SET NULL Set FK column to NULL in child rows
SET DEFAULT Set FK column to its default value
RESTRICT Prevent deletion/update if child rows exist (default)
NO ACTION Similar to RESTRICT (checked at end of transaction) 
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id)
        REFERENCES customers(customer_id)
        ON DELETE CASCADE
        ON UPDATE SET NULL
);

Q14. Can a Foreign Key column have NULL values?

Yes. A NULL FK value means “no relationship” — it doesn’t violate referential integrity. This allows optional relationships.

-- employee may or may not be assigned to a department
INSERT INTO employees (emp_id, name, dept_id) VALUES (101, 'Chirag', NULL);

ADVANCED LEVEL

Q15. What is the difference between RESTRICT and NO ACTION for Foreign Key constraints?

Both prevent deletion of a parent row when child rows exist, but the timing differs:

  • RESTRICT: Checked immediately when the statement executes.
  • NO ACTION: Checked at the end of the transaction (deferred check).

This matters in cases where you’re doing multiple operations in one transaction — NO ACTION gives you flexibility to fix the inconsistency before the transaction commits.

Q16. Can a Composite Primary Key include a NULL column?

No. Every column that is part of a Primary Key must be NOT NULL. This is a SQL standard rule.

Q17. Can a table have multiple Foreign Keys pointing to the same parent table?

Yes. A table can have multiple FK columns all referencing the same parent table, or even the same column in the parent.

CREATE TABLE flights (
    flight_id INT PRIMARY KEY,
    origin_city_id INT,
    destination_city_id INT,
    FOREIGN KEY (origin_city_id) REFERENCES cities(city_id),
    FOREIGN KEY (destination_city_id) REFERENCES cities(city_id)
);

Q18. What is a Deferrable Constraint? (PostgreSQL)

In PostgreSQL, constraints can be deferred — meaning their check is postponed until the end of the transaction instead of being enforced immediately.

-- PostgreSQL syntax
ALTER TABLE orders
    ADD CONSTRAINT fk_customer
    FOREIGN KEY (customer_id)
    REFERENCES customers(customer_id)
    DEFERRABLE INITIALLY DEFERRED;

Useful when you need to insert rows in a circular dependency within one transaction.

Q19. Commonly Ignored: Can you DROP a Primary Key if a Foreign Key references it?

No. You must first drop the Foreign Key constraint on the child table, and only then can you drop the Primary Key.

-- Step 1: Drop the FK on child
ALTER TABLE orders DROP FOREIGN KEY fk_customer;

-- Step 2: Now drop the PK on parent
ALTER TABLE customers DROP PRIMARY KEY;

Q20. Commonly Ignored: Does adding a Foreign Key automatically create an index?

  • MySQL (InnoDB): YES — automatically creates an index on the FK column if one doesn’t exist.
  • PostgreSQL / SQL Server: NO — you must manually create an index on the FK column.

This is a very common performance pitfall. Always index FK columns to speed up JOINs.

-- Best practice: always do this in PostgreSQL/SQL Server
CREATE INDEX idx_orders_customer_id ON orders(customer_id);

Q21. Commonly Ignored: What happens to indexes when you add a Primary Key to an existing table?

In most databases (especially MySQL InnoDB), the Primary Key becomes the clustered index — meaning the actual table data is physically sorted by the PK. If you change the PK on an existing table, the entire table is physically reorganized. This can be a costly operation on large tables.

Q22. Tricky: Can a column be both a Primary Key and a Foreign Key?

Yes! This is common in one-to-one relationship tables where the child table’s PK is also a FK referencing the parent.

CREATE TABLE employee_details (
    emp_id INT PRIMARY KEY,            -- PK
    bio TEXT,
    FOREIGN KEY (emp_id) REFERENCES employees(emp_id)  -- also FK
);

2. TRIGGERS IN SQL

BASIC LEVEL

Q23. What is a Trigger in SQL?

A Trigger is a special stored procedure that automatically executes (fires) in response to a specific event on a table or view — such as INSERT, UPDATE, or DELETE.

You don’t call triggers manually. The database engine fires them automatically.

Q24. What are the types of triggers based on timing?

Type When it fires
BEFORE Trigger Fires BEFORE the DML operation is executed
AFTER Trigger Fires AFTER the DML operation completes
INSTEAD OF Trigger Fires IN PLACE OF the operation (commonly on views)

Q25. What are the types of triggers based on event?

  • INSERT trigger — fires when a row is inserted
  • UPDATE trigger — fires when a row is updated
  • DELETE trigger — fires when a row is deleted

You can combine them: a single trigger can respond to INSERT OR UPDATE OR DELETE.

Q26. Write a basic trigger that logs every new employee insert.

-- Audit table
CREATE TABLE employee_audit (
    audit_id INT AUTO_INCREMENT PRIMARY KEY,
    emp_id INT,
    action_type VARCHAR(20),
    action_time DATETIME
);

-- AFTER INSERT trigger
CREATE TRIGGER trg_after_employee_insert
AFTER INSERT ON employees
FOR EACH ROW
BEGIN
    INSERT INTO employee_audit (emp_id, action_type, action_time)
    VALUES (NEW.emp_id, 'INSERT', NOW());
END;

Q27. What are NEW and OLD in triggers?

Keyword Available In Meaning
NEW INSERT, UPDATE triggers The new row being inserted or the new value after update
OLD DELETE, UPDATE triggers The existing row being deleted or the old value before update 
-- BEFORE UPDATE trigger: prevent salary decrease
CREATE TRIGGER trg_no_salary_decrease
BEFORE UPDATE ON employees
FOR EACH ROW
BEGIN
    IF NEW.salary < OLD.salary THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Salary cannot be decreased.';
    END IF;
END;

Q28. What is FOR EACH ROW in a trigger?

It means the trigger fires once for each row affected by the DML statement.

  • Row-level trigger (FOR EACH ROW): fires per affected row.
  • Statement-level trigger: fires once per DML statement regardless of how many rows are affected. (Available in PostgreSQL and SQL Server, not MySQL.)

MySQL only supports row-level triggers.

INTERMEDIATE LEVEL

Q29. What is an INSTEAD OF trigger? When would you use it?

An INSTEAD OF trigger replaces the actual DML operation. It is most commonly used on views that cannot be directly updated (e.g., views based on multiple tables or containing aggregations).

-- PostgreSQL / SQL Server example
CREATE TRIGGER trg_instead_of_insert_on_view
INSTEAD OF INSERT ON employee_summary_view
FOR EACH ROW
BEGIN
    -- redirect insert to the actual base tables
    INSERT INTO employees (emp_id, name) VALUES (NEW.emp_id, NEW.name);
    INSERT INTO departments (dept_id, dept_name) VALUES (NEW.dept_id, NEW.dept_name);
END;

Q30. Can a trigger call a stored procedure?

Yes. A trigger body can call a stored procedure.

CREATE TRIGGER trg_after_order_insert
AFTER INSERT ON orders
FOR EACH ROW
BEGIN
    CALL update_customer_stats(NEW.customer_id);
END;

Q31. Can a trigger fire another trigger? What is a mutating trigger problem?

Yes, a trigger can indirectly fire another trigger — this is called a cascading trigger. Most databases let you control the nesting level.

The mutating table problem occurs when a row-level trigger tries to query or modify the same table that caused the trigger to fire, which creates a conflict because the table is in a “mid-change” state. This is most commonly seen in Oracle.

Q32. What is the difference between BEFORE and AFTER triggers? When do you use each?

BEFORE Trigger AFTER Trigger
Timing Before data is written After data is written
Can modify NEW values? YES — can change what gets inserted/updated NO — data already committed
Use case Validation, data transformation Auditing, cascading actions, logging 
-- BEFORE: Clean up data before inserting
CREATE TRIGGER trg_before_insert_user
BEFORE INSERT ON users
FOR EACH ROW
BEGIN
    SET NEW.email = LOWER(TRIM(NEW.email));
END;

-- AFTER: Log what was changed
CREATE TRIGGER trg_after_delete_user
AFTER DELETE ON users
FOR EACH ROW
BEGIN
    INSERT INTO deleted_users_log (user_id, deleted_at)
    VALUES (OLD.user_id, NOW());
END;

Q33. How do you drop a trigger?

DROP TRIGGER IF EXISTS trg_after_employee_insert;

-- In SQL Server: must specify schema
DROP TRIGGER dbo.trg_after_employee_insert;

Q34. How do you disable/enable a trigger without dropping it? (SQL Server)

-- SQL Server
DISABLE TRIGGER trg_after_employee_insert ON employees;
ENABLE TRIGGER trg_after_employee_insert ON employees;

-- Disable ALL triggers on a table
DISABLE TRIGGER ALL ON employees;

MySQL does not natively support disabling triggers — you’d need to drop and recreate them.

Q35. Can you have multiple triggers of the same type on the same table?

  • MySQL: Yes, and since MySQL 5.7.2 you can control execution order using FOLLOWS or PRECEDES.
  • SQL Server: Yes, multiple AFTER triggers per event.
  • Oracle: Yes, uses order of creation by default.
-- MySQL: control order
CREATE TRIGGER trg_second
AFTER INSERT ON employees
FOR EACH ROW
FOLLOWS trg_first
BEGIN
    -- runs after trg_first
END;

ADVANCED LEVEL

Q36. Commonly Ignored: Can a trigger raise an error to abort the DML operation?

Yes. You can use SIGNAL (MySQL/MariaDB) or RAISERROR/THROW (SQL Server) to raise an error and roll back the operation.

-- MySQL: prevent inserting a negative salary
CREATE TRIGGER trg_validate_salary
BEFORE INSERT ON employees
FOR EACH ROW
BEGIN
    IF NEW.salary < 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Salary cannot be negative.';
    END IF;
END;

When a trigger raises an error in a BEFORE trigger, the entire statement is rolled back.

Q37. Commonly Ignored: Are triggers included in transactions?

Yes. Triggers execute within the same transaction as the DML that fired them. If the trigger raises an error or if a ROLLBACK is executed, both the original DML and the trigger’s actions are rolled back together.

Q38. What are the performance implications of triggers?

  • Triggers add overhead to every affected DML operation — even simple INSERTs/UPDATEs slow down.
  • They execute invisibly — application code doesn’t know they’re running.
  • Cascading triggers can cause unexpected performance degradation.
  • Avoid complex logic or heavy queries inside triggers.
  • Use triggers only for cross-cutting concerns like auditing, not business logic that belongs in the application layer.

Q39. Commonly Ignored: Can you use SELECT inside a trigger?

Yes, but with caution. You can query other tables.

CREATE TRIGGER trg_check_department
BEFORE INSERT ON employees
FOR EACH ROW
BEGIN
    DECLARE dept_count INT;
    SELECT COUNT(*) INTO dept_count
    FROM departments
    WHERE dept_id = NEW.dept_id;

    IF dept_count = 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Department does not exist.';
    END IF;
END;

Avoid SELECTing from the same table that fired the trigger (mutating table issue).

Q40. Tricky: What is the difference between a trigger and a constraint?

Feature Constraint Trigger
Enforcement Declarative, built-in Programmatic, custom logic
Performance Faster (native) Slower (extra code runs)
Complexity Simple rules only Complex business logic
Transparency Visible in schema Can be hidden/forgotten
Portability Standard SQL Syntax varies per DB

Rule of thumb: Always prefer a constraint over a trigger for simple validation. Use triggers only for logic that cannot be expressed as a constraint.

Q41. Tricky: Do triggers fire on TRUNCATE?

No. TRUNCATE does not fire DELETE triggers in MySQL because TRUNCATE is a DDL operation, not DML — it doesn’t process rows one by one.

In PostgreSQL, statement-level triggers can be configured to fire on TRUNCATE.

Q42. What is a DDL trigger? (SQL Server / Oracle)

A DDL trigger fires in response to schema changes (DDL events) like CREATE TABLE, ALTER TABLE, DROP TABLE — not on data changes.

-- SQL Server: prevent table drops in production
CREATE TRIGGER trg_prevent_drop
ON DATABASE
FOR DROP_TABLE
AS
BEGIN
    PRINT 'You are not allowed to drop tables!';
    ROLLBACK;
END;

3. RANK vs DENSE_RANK (and ROW_NUMBER)

BASIC LEVEL

Q43. What are Window Functions in SQL?

Window functions perform calculations across a set of rows that are related to the current row — but unlike GROUP BY, they do NOT collapse rows. Each row retains its identity and gets its own computed value.

SELECT
    name,
    salary,
    RANK() OVER (ORDER BY salary DESC) AS salary_rank
FROM employees;

Q44. What is RANK()?

RANK() assigns a rank to each row within a partition. If two rows are tied (same value), they get the SAME rank. The next rank SKIPS the number of tied rows.

SELECT
    name,
    salary,
    RANK() OVER (ORDER BY salary DESC) AS rnk
FROM employees;

Example output:

name salary rnk
Alice 90000 1
Bob 85000 2
Carol 85000 2
David 70000 4

Note: rank 3 is skipped because two rows tied at rank 2.

Q45. What is DENSE_RANK()?

DENSE_RANK() also assigns the same rank to tied rows — but it does NOT skip any ranks. The next rank is always the previous rank + 1.

SELECT
    name,
    salary,
    DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rnk
FROM employees;

Example output:

name salary dense_rnk
Alice 90000 1
Bob 85000 2
Carol 85000 2
David 70000 3

No gaps — next rank after 2 is simply 3.

Q46. What is ROW_NUMBER()?

ROW_NUMBER() assigns a unique sequential number to each row. Even if two rows have the same value, they get different numbers. The order of tied rows is arbitrary (unless fully specified by ORDER BY).

SELECT
    name,
    salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num
FROM employees;

Example output:

name salary row_num
Alice 90000 1
Bob 85000 2
Carol 85000 3
David 70000 4

Q47. Side-by-side comparison of ROW_NUMBER, RANK, and DENSE_RANK

SELECT
    name,
    salary,
    ROW_NUMBER()  OVER (ORDER BY salary DESC) AS row_num,
    RANK()        OVER (ORDER BY salary DESC) AS rnk,
    DENSE_RANK()  OVER (ORDER BY salary DESC) AS dense_rnk
FROM employees;
name salary row_num rnk dense_rnk
Alice 90000 1 1 1
Bob 85000 2 2 2
Carol 85000 3 2 2
David 70000 4 4 3
Eve 60000 5 5 4

INTERMEDIATE LEVEL

Q48. What is the PARTITION BY clause in window functions?

PARTITION BY divides the result set into groups (partitions) and the ranking restarts for each partition — similar to GROUP BY but without collapsing rows.

-- Rank employees within each department
SELECT
    name,
    department,
    salary,
    RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS dept_rank
FROM employees;
name department salary dept_rank
Alice Engineering 90000 1
Bob Engineering 85000 2
Carol HR 70000 1
David HR 65000 2

Q49. How do you find the top N employees per department?

A classic interview question. Use ROW_NUMBER or RANK in a subquery/CTE.

-- Top 2 highest-paid employees per department
WITH ranked AS (
    SELECT
        name,
        department,
        salary,
        ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) AS rn
    FROM employees
)
SELECT * FROM ranked WHERE rn <= 2;

Use RANK() instead of ROW_NUMBER() if you want to include ties — ties at rank 2 would both be included.

Q50. When would you choose RANK vs DENSE_RANK vs ROW_NUMBER?

Scenario Best Choice
Need a unique row number (pagination, deduplication) ROW_NUMBER
Medal-style ranking — ties share rank, next rank skips RANK
Leaderboard where gaps in ranks are confusing DENSE_RANK
Finding Nth highest salary DENSE_RANK (most reliable)
Deduplicating rows ROW_NUMBER

Q51. How do you find the 3rd highest salary using DENSE_RANK?

WITH ranked AS (
    SELECT
        salary,
        DENSE_RANK() OVER (ORDER BY salary DESC) AS dr
    FROM employees
)
SELECT salary FROM ranked WHERE dr = 3;

Why DENSE_RANK and not RANK?

Example: salaries are 90k, 85k, 85k, 70k

  • RANK values: 1, 2, 2, 4 — no rank 3 exists!
  • DENSE_RANK values: 1, 2, 2, 3 — rank 3 = 70k ✓

Q52. Commonly Ignored: What happens if ORDER BY has all unique values — do RANK, DENSE_RANK, and ROW_NUMBER differ?

No. If all ORDER BY values are unique (no ties), RANK, DENSE_RANK, and ROW_NUMBER all produce identical output. They only differ when ties exist.

Q53. Can you use window functions in a WHERE clause?

No! Window functions cannot be used directly in WHERE or HAVING clauses. You must wrap them in a subquery or CTE first.

-- WRONG
SELECT name, salary
FROM employees
WHERE RANK() OVER (ORDER BY salary DESC) = 1;

-- CORRECT
WITH ranked AS (
    SELECT name, salary,
           RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM employees
)
SELECT name, salary FROM ranked WHERE rnk = 1;

Q54. What is the difference between PARTITION BY and GROUP BY?

Feature GROUP BY PARTITION BY (Window)
Collapses rows? YES — one output row per group NO — all rows remain
Used with Aggregate functions (SUM, COUNT, AVG) Window functions (RANK, ROW_NUMBER, SUM OVER)
Can access individual row data? Only via aggregation Yes

Q55. What is a named window / WINDOW clause?

SQL standard (and MySQL 8+, PostgreSQL) allows you to name a window definition and reuse it, avoiding repetition.

SELECT
    name,
    salary,
    RANK()       OVER w AS rnk,
    DENSE_RANK() OVER w AS d_rnk,
    ROW_NUMBER() OVER w AS rn
FROM employees
WINDOW w AS (PARTITION BY department ORDER BY salary DESC);

ADVANCED LEVEL

Q56. Commonly Ignored: What is the FRAME clause in window functions?

The frame clause defines which rows around the current row are included in the calculation. Relevant for aggregate window functions like SUM OVER or AVG OVER.

-- Running total of salary
SELECT
    name,
    salary,
    SUM(salary) OVER (
        ORDER BY emp_id
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total
FROM employees;

Common frame types:

  • ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW — running total
  • ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING — 3-row rolling average
  • ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING — entire partition

Q57. How do you delete duplicate rows using ROW_NUMBER?

A classic and very commonly asked interview question.

-- Keep only the first occurrence, delete the rest
WITH cte AS (
    SELECT *,
           ROW_NUMBER() OVER (PARTITION BY email ORDER BY created_at ASC) AS rn
    FROM users
)
DELETE FROM cte WHERE rn > 1;

ROW_NUMBER is ideal here because we need exactly one row per group — ties must be broken.

Q58. Tricky: Can RANK() produce the same result as DENSE_RANK() in some cases?

Yes — when there are no ties in the ORDER BY column within any partition, both produce identical results because there are no gaps to introduce.

Q59. What are LAG and LEAD functions?

LAG and LEAD are window functions that let you access data from previous or next rows without a self-join.

SELECT
    name,
    salary,
    LAG(salary, 1)  OVER (ORDER BY emp_id) AS prev_salary,
    LEAD(salary, 1) OVER (ORDER BY emp_id) AS next_salary,
    salary - LAG(salary, 1) OVER (ORDER BY emp_id) AS salary_diff
FROM employees;

Q60. Commonly Ignored: What is NTILE()?

NTILE(n) divides rows into n equal-sized buckets and assigns a bucket number to each row. Useful for percentile/quartile calculations.

-- Divide employees into 4 salary quartiles
SELECT
    name,
    salary,
    NTILE(4) OVER (ORDER BY salary DESC) AS quartile
FROM employees;

Quartile 1 = top 25% earners, Quartile 4 = bottom 25%.

Q61. Tricky: What happens with NULLs in ORDER BY within window functions?

NULLs in the ORDER BY column are treated as equal to each other. Default ordering varies:

  • PostgreSQL: NULLs appear LAST for ASC, FIRST for DESC.
  • MySQL/SQL Server: NULLs appear FIRST for ASC.

Use NULLS FIRST or NULLS LAST in PostgreSQL to control this.

-- PostgreSQL
RANK() OVER (ORDER BY salary DESC NULLS LAST)

Q62. Commonly Ignored: Are window functions evaluated before or after WHERE?

Window functions are evaluated AFTER the WHERE clause but BEFORE the outer SELECT or ORDER BY. This means:

  • Rows filtered by WHERE are excluded before the window function runs.
  • You cannot filter by window function result in the same query level — must use CTE or subquery.

Q63. What is PERCENT_RANK() vs CUME_DIST()?

Both are window functions for statistical distribution.

Function Formula Range
PERCENT_RANK (rank - 1) / (total rows - 1) 0 to 1
CUME_DIST rows with value <= current / total rows > 0 to 1 
SELECT
    name,
    salary,
    PERCENT_RANK() OVER (ORDER BY salary) AS pct_rank,
    CUME_DIST()    OVER (ORDER BY salary) AS cume_dist
FROM employees;

Q64. Interview Classic: Find employees earning more than the average salary of their department.

SELECT name, department, salary
FROM (
    SELECT
        name,
        department,
        salary,
        AVG(salary) OVER (PARTITION BY department) AS dept_avg
    FROM employees
) t
WHERE salary > dept_avg;

Q65. Interview Classic: Find the second highest salary without using TOP/LIMIT.

-- Using DENSE_RANK
WITH ranked AS (
    SELECT salary,
           DENSE_RANK() OVER (ORDER BY salary DESC) AS dr
    FROM employees
)
SELECT MAX(salary) FROM ranked WHERE dr = 2;

-- Alternative using subquery
SELECT MAX(salary) FROM employees
WHERE salary < (SELECT MAX(salary) FROM employees);
